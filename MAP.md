# Карта: где что искать

Одна дверь для новой сессии. Не пересказывает содержимое — говорит, куда идти.

## Вопрос → документ

| Вопрос | Куда |
|---|---|
| Кто есть кто, как устроен процесс, релизы, запреты | [`CHARTER.md`](CHARTER.md) |
| Кому писать, как передаётся работа | [`roles/TEAM.md`](roles/TEAM.md) |
| Что значит слово, которое все говорят по-разному | [`GLOSSARY.md`](GLOSSARY.md) |
| Почему экосистема устроена так | [`decisions/`](decisions/) |
| Правило, которое читают два и более продукта | [`contracts/`](contracts/) |
| Почему **внутри продукта** сделано так | `<продукт>/docs/decisions/` |
| Как устроен продукт | `<продукт>/AGENTS.md`, затем его `docs/` |
| Как считаются деньги, как работаем с людьми | репозиторий `docs`, раздел «дело» |
| Подходы и внутреннее устройство системы | репозиторий `docs`, раздел «система» |
| На что уже наступали, где остановились | репозиторий `context`, память сессий |
| Что лежит в рабочей папке и чем её обслуживать | репозиторий `workspace`, `README.md` |

## Четыре слоя

Сверху вниз, конфликт решает верхний:

1. **Канон** — этот репозиторий: устав, решения экосистемы, контракты.
   Обязателен для всех, меняется веткой с ревью архитектора.
2. **Продукты** — код, решения продукта, его устройство. Правда о поведении —
   код и тесты.
3. **Знание** — репозиторий `docs`: как устроено дело и как устроена система.
   Живёт дольше кода, читается людьми.
4. **Память** — репозиторий `context`: опыт сессий и грабли. Подсказывает, но
   полномочий не даёт: в цепочке разрешения конфликтов из устава её нет.

Правило принадлежности: **зависит ли от этого кто-то снаружи.** Зависит другой
продукт — в канон. Живёт внутри одного дома — в продукт, рядом с кодом.
Переживёт переписывание кода — в знание. Опыт сессии — в память.

## Продукты

| Репозиторий | Что это | Домен |
|---|---|---|
| `website` | публичный сайт | `summy.ru` |
| `crm` | управленка: процессы, зарплата, склад, клиенты | `admin.summy.ru` |
| `master-app` | кабинет мастера: клиент `web/` + прослойка `bff/` | `master.summy.ru` |
| `client-app` | приложение клиента — заведён, кода нет | — |
| `backend` | данные и вся продуктовая логика | внутренний |

Служебные: `governance` — канон, `docs` — знание, `context` — память,
`workspace` — рабочая папка. Локально, без облака: `data` — схема базы,
миграции и импортёры.

## Чего в каноне нет намеренно

Живого состояния: какая версия на бою, на какой ветке checkout, что сейчас
чинится. Это спрашивают у системы, а не у документа — прод сообщает версию
сам, состояние ветки показывает Git. Документ, повторяющий живое состояние,
устаревает молча и начинает врать.
