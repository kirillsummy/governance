# SUMMY · документация разработки

Единый вход в продукт, архитектуру и правила SUMMY. Политика репозитория — в
[ветках](docs/branches.md). Если нужного контекста ещё нет, для агента начни с
[AGENTS.md](AGENTS.md); для знакомства с системой — с
[продукта](docs/product.md), [общей схемы](docs/architecture/README.md) и [текущего состояния](docs/current-state.md).
Изменения любого репозитория `kirillsummy`, выполненные человеком или LLM,
отражаются здесь по [правилу устава](CHARTER.md#что-документируем-а-что-нет):
Governance — единая база знаний, а не отдельный архив после релиза.

## Как читать

Обзоры не подменяют код и не доказывают состояние production. Утверждения имеют
источник/SHA, feature отделён от базы, исторические наблюдения — от текущего состояния.
Уникальные прежние контракты сохранены; исходные варианты DOC доступны в Git-истории.
Старый отдельный `kirillsummy/docs` остаётся источником бизнес-знаний, `context` —
частной памятью, `workspace` — инструментами. Их содержимое не удалялось.

Governance публичный. Здесь нет секретов, дампов и персональных данных.
Ссылки на приватные исходники требуют соответствующего доступа GitHub.

Допустимые проверки перечислены в [конвенциях](docs/conventions.md), а разрешение
на их запуск регулируют [ограничения](ai/RESTRICTIONS.md).
