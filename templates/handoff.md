# Шаблон хендоффа (передача работы)

Финал каждой рабочей сессии. Коротко и проверяемо; получатель ревьюит по
этой сводке, не восстанавливая контекст сессии.

Носитель — описание Pull Request (сдача кода) плюс письмо релиз-инженеру с
той же финальной строкой. Файл `HANDOFF-<дата>-<тема>.md` в корне рабочего
пространства — только для адресатов, до которых письма не ходят (Codex,
операционная команда, владелец без сессии), и для результатов без PR;
исполнитель помечает исполнение прямо в таком файле. Повторная сдача — новый
коммит в тот же PR и строка в «Исполнении» задания, не новая версия файла.

```markdown
Кому: <роль-получатель> · От: <роль-отправитель> · Репо: <owner/repo> ·
Ветка: <ветка> · Коммит: <полный SHA>

## Сделано
- <что и где; ключевые файлы>
- <решения, принятые самостоятельно, и почему>

## Проверено
- <команды и результат: тесты N OK, lint, build>
- <что проверено руками/в превью>

## Осталось / развилки
- <что сознательно НЕ сделано и почему — «не считать недоделкой»>
- <вопросы владельцу/релиз-инженеру, если упёрся в чужой продукт или бренд>

## Совместимость
- Миграции: <нет | какие и почему безопасны>
- Env/флаги: <новые переменные, дефолты; поведение прода при деплое без правки .env>
- Стыки продуктов: <не трогает | какой контракт и что меняется>

Релиз-инженеру: проведи ревью и смержи <ветка> (commit <полный SHA>)
```

**Хендофф просит ревью и мерж — выкатку он не просит:**
выкатку разрешает владелец отдельной явной фразой («выкатывай X»). Деньги,
миграции, права, удаление — со ссылкой на решение владельца в тексте
хендоффа.

Правила после отправки: **отданный коммит заморожен** — `amend`/`rebase`/
`force push` по нему запрещены; правки по ревью — новыми коммитами поверх,
с новым SHA в новом хендоффе. Не готово даже к мержу → вместо последней строки:
`Релиз-инженеру: не мержить, ветка в работе`.
