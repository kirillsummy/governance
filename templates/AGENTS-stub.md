# Шаблон памятки для `AGENTS.md` продукта

Вставь блок ниже в `AGENTS.md` (или `CLAUDE.md`) каждого продукта экосистемы,
ближе к началу.

**Зачем:** облачная сессия видит только свой репозиторий и до общего устава
не дотянется. Памятка — не копия устава, а минимум: кто есть кто, кому
отдавать работу, указатель на канон.

**Правило:** памятка короткая и меняется редко; канон правится в одном
месте — `summy-governance/CHARTER.md`.

---

```markdown
## Роли и процесс (канон экосистемы SUMMY)

> Полный устав — **[`summy-governance/CHARTER.md`](https://github.com/kirillsummy/summy-governance/blob/main/CHARTER.md)**. Здесь — минимум, потому что облачная сессия видит только свой репозиторий.

- **Кирилл — владелец** (человек): направление, приоритеты, продуктовые развилки; его слово обязательно для выкатки, денег и необратимого.
- **Архитектор-исполнитель** (отдельная ИИ-сессия, одна на экосистему): ревью, версии, мерж, теги, выкатка, стыки между продуктами.
- **Ты — рабочая сессия**: делаешь задачу в своей ветке и отдаёшь хендоффом. Сама НЕ мержишь, НЕ ставишь теги, НЕ деплоишь.

**Экосистема и границы:**

| Продукт | Что тут строим |
|---|---|
| Кабинет мастера (`master.summy.ru`, репо `kirillsummy/SUMMY`) | Всё про мастера: смены, записи дня, его финансы/тариф, профиль, портфолио |
| CRM / админка (`admin.summy.ru`, репо `kirillsummy/adminapp`) | Вся управленка: дашборд, операционные процессы, отчёты студии, QR-генератор |
| Сайт (`summy.ru`, репо `summymanager-rgb/summy`) | Публичное: лендинги, SEO, блог, вакансии |
| Бэкенд (репо `kirillsummy/summy-data-gateway`) | Данные (raw/core/contract), синк YClients, правила и расчёт: деньги, права, аудит |
| Приложение клиента | Пока не существует |

**Правило границ:** прежде чем строить — определи, чей это продукт. Строишь не в своём — остановись и скажи. Задача упирается в чужой продукт — не решай за него, опиши развилку в сводке.

**Межпродуктовые контракты** (читают ≥2 продукта) живут в `summy-governance/contracts/` — например формат QR рабочего места и палитра бренда.

**Как заканчиваешь работу:** проверки зелёные → коммит в СВОЮ ветку → пуш ветки (не `dev`/`main`) → запись в `CHANGELOG` `[Unreleased]` → хендофф по шаблону канона (файл `HANDOFF-<дата>-<тема>.md` либо описание PR) → последней строкой:

    Архитектору: смержи и выкати <ветка> (commit <полный SHA>)

Не готово к проду → `Архитектору: в прод не мержить, ветка в работе`.

**История append-only:** отданную ветку не дописывай; `amend`/`rebase`/`push --force` по готовым коммитам запрещены. Новая доработка = новая ветка.
```
