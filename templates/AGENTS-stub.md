# Шаблон памятки для `AGENTS.md` продукта

Вставь блок ниже в `AGENTS.md` (или `CLAUDE.md`) каждого продукта экосистемы,
ближе к началу.

**Зачем:** облачная сессия видит только свой репозиторий и до общего устава
не дотянется. Памятка — не копия устава, а минимум: кто есть кто, кому
отдавать работу, указатель на канон.

**Правило:** памятка короткая и меняется редко; канон правится в одном
месте — `governance/CHARTER.md`.

---

```markdown
## Роли и процесс (канон экосистемы SUMMY)

> Полный устав — **[`governance/CHARTER.md`](https://github.com/kirillsummy/governance/blob/main/CHARTER.md)**. Здесь — минимум, потому что облачная сессия видит только свой репозиторий.

- **Кирилл — владелец** (человек): направление, приоритеты, продуктовые развилки; его слово обязательно для выкатки, денег и необратимого.
- **Релиз-инженер** (отдельная ИИ-сессия, одна на экосистему): приёмка, ревью, версии, мерж в базовые ветки, теги, выкатка. Работает без владельца — к нему приходит построенное.
- **Архитектор** (сессия под решение): границы продуктов, контракты, стек, версии рантаймов, что рефакторить. Работает вместе с владельцем, сам не мержит.
- **Ты — рабочая сессия**: делаешь задачу в своей ветке и отдаёшь хендоффом. Сама НЕ мержишь, НЕ ставишь теги, НЕ деплоишь.

**Экосистема и границы:**

| Продукт | Что тут строим |
|---|---|
| Кабинет мастера (`master.summy.ru`, репо `kirillsummy/master-app`) | Всё про мастера: смены, записи дня, его финансы/тариф, профиль, портфолио |
| CRM / админка (`admin.summy.ru`, репо `kirillsummy/crm`) | Вся управленка: дашборд, операционные процессы, отчёты студии, QR-генератор |
| Сайт (`summy.ru`, репо `summymanager-rgb/summy`) | Публичное: лендинги, SEO, блог, вакансии |
| Бэкенд (репо `kirillsummy/backend`) | Данные (raw/core/contract), синк YClients, правила и расчёт: деньги, права, аудит |
| Приложение клиента | Пока не существует |

**Правило границ:** прежде чем строить — определи, чей это продукт. Строишь не в своём — остановись и скажи. Задача упирается в чужой продукт — не решай за него, опиши развилку в сводке.

**Межпродуктовые контракты** (читают ≥2 продукта) живут в `governance/contracts/` — например формат QR рабочего места и палитра бренда.

**Как заканчиваешь работу:** проверки зелёные → коммит в СВОЮ ветку → пуш только СВОЕЙ feature-ветки — не пушить и не мержить ни в одну защищённую ветку продукта (перечень — в AGENTS.md продукта и таблице «Ветки» устава) → запись в `CHANGELOG` `[Unreleased]` → хендофф по шаблону канона (файл `HANDOFF-<дата>-<тема>.md` либо описание PR) → последней строкой:

    Релиз-инженеру: проведи ревью и смержи <ветка> (commit <полный SHA>)

Выкатку разрешает только владелец отдельной фразой. Не готово даже к мержу → `Релиз-инженеру: не мержить, ветка в работе`.

**История append-only:** отданный коммит заморожен — `amend`/`rebase`/`push --force` по нему запрещены; правки по ревью — новыми коммитами поверх, с новым SHA в новом хендоффе.
```
