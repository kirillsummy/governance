# Как экономить контекст и токены в SUMMY

Канонические правила работы с контекстом находятся в
[workflow](WORKFLOW.md). Дополнительные приёмы для объёмных Git-задач:

1. Начинай с точного последнего SHA. Обычно достаточно remote, status, веток,
   `merge-base`, краткого log и `diff --stat`; исходники открывай только для
   конкретного вопроса или конфликта.
2. В `singular` сравнивай исходные головы разработок, а не целое архивное
   дерево. Достижимость коммита и наличие работающей функции — разные факты.
3. Независимые чтения группируй, ограничивай вывод нужными строками и файлами.
   При смене SHA сначала изучай разницу.
4. Сначала переноси совместимое. По смысловым конфликтам дай владельцу
   короткий выбор; не заменяй новые решения старыми ради чистого merge.
5. Записывай результат один раз: дата, точные SHA, перенесённые части,
   оставшиеся альтернативы и пределы проверки. Остальные документы ссылаются
   на этот журнал. Финальный ответ — результат и важные ограничения.

Полномочия и запуск проверок определяют [ограничения](RESTRICTIONS.md).
