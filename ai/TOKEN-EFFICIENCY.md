# Как экономить контекст и токены в SUMMY

1. Сначала используй контекст текущей задачи и точный последний SHA. Повторно
   не читай весь Governance: сверь вершину и прочитай только изменившиеся
   правила/разделы. Новая сессия всё равно читает обязательный вход AGENTS.
2. Начинай с карты репозиториев, README и краткого журнала изменений.
   Для Git-задач достаточно remote, status, веток, `merge-base`, краткого log
   и `diff --stat`; исходники открывай только для конкретного вопроса/конфликта.
3. В `singular` сравнивай исходные головы разработок, а не целое архивное
   дерево. Достижимость коммита и наличие работающей функции — разные факты.
4. Независимые чтения группируй, ограничивай вывод нужными строками и файлами.
   Не перечитывай одну и ту же документацию и не сканируй все репозитории
   после каждой мелкой правки. При смене SHA перечитывай только разницу.
5. Сначала переноси совместимое. По смысловым конфликтам дай владельцу
   короткий выбор; не заменяй новые решения старыми ради чистого merge.
6. Не запускай тесты, сборки, миграции и deployment вопреки ограничениям
   задачи. Не объявляй слияние проверенным приложением или выкаткой.
7. Записывай результат один раз: дата, точные SHA, перенесённые части,
   оставшиеся альтернативы и пределы проверки. Остальные документы ссылаются
   на этот журнал. Финальный ответ — результат и важные ограничения.

Эта памятка не отменяет [ограничения](RESTRICTIONS.md) и [порядок работы](WORKFLOW.md).
