# Состояние TEST и БД

Начни с [инфраструктуры](../../../docs/infrastructure.md#подключение-к-test-и-бд) и [модели БД](../../../docs/database.md). Сверь полный SHA `origin/test` затронутых продуктов отдельно от работающих VERSION/образов на TEST. `test` в Git не доказывает выкладку; health не доказывает пользовательский сценарий.

На ПК Юры локальные `TEST-ACCESS.md` и `.ssh/test-db.ps1` описывают `Status`, `Shell`, `Psql` и `Tunnel`. Проверь их наличие и доступ в этой сессии. Из песочницы Codex штатный ключ может читаться только пользовательским процессом; применяй разрешённый запуск, не копируя ключ и не ослабляя проверку SSH host key. На другой машине используй только её подтверждённый доступ. `Status` не даёт ревизию БД и может не перечислять client-app — проверь их отдельно, если они важны задаче.

При работе с БД подключайся через подтверждённый туннель и персональную роль. Для проверки схемы читай `alembic_version` и сопоставляй её с миграциями точного SHA. Не выводи клиентские строки, пароль, дамп или значения `.env` в чат и Governance. SQL-запись, миграция и restore требуют отдельного поручения и правил [ограничений](../../RESTRICTIONS.md#проверки).

Отчёт: время снимка, продукт, Git SHA, фактический VERSION/образ, ревизия БД при необходимости и граница того, что проверено. Состояние production не выводи из TEST-доступа.
