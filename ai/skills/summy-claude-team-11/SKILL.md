# Менеджер и десять исполнителей

Применяй к явно порученному набору задач: $ARGUMENTS. Читай актуальные Governance
AGENTS.md, CHARTER.md, ai/WORKFLOW.md и инструкции продуктов. Этот навык задаёт
координацию, а не новые полномочия на публикацию или выпуск.

## Выбери механизм

- **Интерактивный официальный Claude Code:** Agent Teams включаются переменной
  `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` только для данного запуска. Основная
  сессия — менеджер, до десяти teammates — исполнители. На Windows используй
  `--teammate-mode in-process`. Не требуй tmux. Назначай Opus и наследуй high.
- **Окно 8770 и runner с `-p`:** это отдельные управляемые сеансы; native teammates
  в этом режиме не создаются. Не утверждай, что десять строк списка образуют
  Agent Team. Менеджер может использовать обычные subagents для своего задания,
  но окно не обещает отдельную строку и прямую отправку каждому subagent.
- Для уже работающих самостоятельных сеансов подготовь менеджеру реестр и
  handoff. Сообщения между ними отправляй только при прямом поручении владельца
  через поддерживаемый механизм. Не возобновляй занятую sessionId параллельно,
  не читай credentials или внутренние файлы аккаунта ради связи.

Перед созданием команды сверь фактические возможности установленного CLI и
поддержку teammates в текущем режиме. Если режим их не поддерживает, дай точный
способ запуска из [инструкции](references/usage.md), не подменяй его фиктивными
потоками. Не включай экспериментальную настройку глобально.

## Работа менеджера

1. Сверь существующие задачи и работающие сеансы. Сохрани чужую работу; не
   создавай повторные исполнители одной задачи. Разложи поручение на независимые
   результаты и зависимости. «11» — менеджер плюс десять исполнителей, а не
   одиннадцать исполнителей дополнительно.
2. Для каждого исполнителя задай задачу, критерий завершения, продукт, список
   принадлежащих ему файлов, рабочий каталог, базовый SHA и разрешённые действия.
   Не назначай десять работ ради заполнения слотов. При меньшем числе независимых
   задач объясни, какие роли ждут зависимостей или проводят независимое ревью.
3. Изолируй запись: отдельный detached worktree каждого продукта на свежем
   согласованном SHA; политика веток — docs/branches.md. Native `--worktree`
   автоматически может создавать ветки и сам по себе не соответствует политике
   SUMMY. Teammates могут начать в каталоге менеджера: до первой записи явно
   направь каждого в принадлежащий ему worktree. Общие миграции, OpenAPI,
   CHANGELOG и очереди выпуска имеют одного назначенного автора/интегратора.
4. Веди общую очередь задач штатными Task-инструментами, если они доступны;
   иначе — один локальный реестр менеджера. Поля: задача/исполнитель/сеанс,
   продукт/worktree/base SHA, владение файлами, зависимости, этап, commit SHA,
   отчёт, проведённые и непроведённые проверки, остаток. Данные сотрудников,
   секреты и транскрипты в публичный Governance не помещай.
5. Менеджер распределяет, снимает пересечения и принимает отчёты; не пишет
   одновременно те же файлы. При конфликте владения останови только пересекающуюся
   работу и перераспредели её. Уточнения владельца адресуй конкретному
   исполнителю через штатные сообщения, сохраняя границу исходной задачи.
6. На контрольных точках отличай «код готов», «опубликован», «Dev доставлен»,
   «Prod доставлен» и «сценарий проверен». Сверяй diff и полные SHA, а не только
   отметку завершения. Ревью выполняет другой исполнитель; автор не принимает
   собственный результат. Проверки — в объёме явно согласованного решения.
7. Интеграцией и внешними записями владеет один назначенный участник. Исполнители
   передают точные коммиты, не публикуют общую ветку и не выкладывают серверы
   конкурентно. Существующее разрешение на Prod не переносится на новые задачи.
8. Заверши явным реестром готового/остатков. Сохрани коммиты и отчёты, затем
   штатно попроси teammates завершиться. Не останавливай чужие процессы.
   После перезапуска восстанови работу по реестру: `/resume` менеджера не
   гарантирует восстановления in-process teammates.

Показывай число **фактически** запущенных исполнителей. Общие ограничения
аккаунта не обходи дополнительными сеансами; при лимите сохраняй результат и
показывай ожидание. Не создавай расписаний и бесконечных проверок статуса.
