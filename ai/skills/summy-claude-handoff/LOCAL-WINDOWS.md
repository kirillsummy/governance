# Claude Code для SUMMY

## Граница использования аккаунта

Используй только официальный неизменённый Claude Code через терминал на компьютере владельца с его собственным входом. Связь с Claude не веди через MCP; запускай Claude Code с `--strict-mcp-config` и без `--mcp-config`, чтобы не загружать MCP-серверы из других настроек. Не извлекай, не копируй и не передавай OAuth-токены, cookies, ключи или файлы сессий; не подключай подписку к стороннему клиенту через эти данные. Не обходи лимиты, защиту и проверки Anthropic, не запускай массовые фоновые запросы и не предоставляй доступ к аккаунту другим пользователям. Поручения должны соответствовать правилам Anthropic: никакого несанкционированного доступа к системам, вредоносного кода, мошенничества, нарушения приватности или имитации реальных людей для обмана. Если способ запуска или задача вызывают сомнение в допустимости, сначала проверь актуальные официальные условия. Владелец разрешил передавать его поручения Claude; это не разрешает выдавать ответы Claude за слова человека при общении с третьими лицами.

Не упоминай имя владельца в новых промтах, поручениях, статусах и сообщениях Claude. Обращайся без имени; при необходимости используй роль «разработчик-координатор» или «владелец поручения». Исторические журналы не переписывай.

Этот навык применяй из любого чата локального проекта SUMMY. Каталог репозиториев: `C:\Users\523ur\Documents\MyProjects\Summy`; входной каталог чатов: `C:\Users\523ur\OneDrive\Документы\ChatGPT\Summy`. Перед поручением прочитай текущие `AGENTS.md`, `governance/AGENTS.md` и относящиеся к задаче правила. Локальный `CLAUDE.md` в каталоге репозиториев задаёт Claude постоянную роль; `\.claude\settings.local.json` добавляет входной каталог и включает его проектную память. Проверяй наличие и действительное чтение этих файлов, не считай их наличия достаточным доказательством доступа.

## Передача и наблюдение

1. Сверь Git-состояние затронутых репозиториев, задачу YouTrack и уже запущенные сеансы Claude. Сохрани чужие изменения. Заранее разбери продуктовый контекст и подготовь в UTF-8 файле поручение с целью, подтверждёнными бизнес-правилами, общей концепцией решения, межпродуктовыми контрактами, критериями приёмки, важными ограничениями совместимости, разрешёнными проверками и границей внешних действий. Самостоятельно решай технические и продуктовые развилки, которые уже следуют из утверждённого поведения и Governance, чтобы Claude не повторял этот анализ. Новые формулы денег, права, ответственность, персональные данные и изменение бизнес-смысла не утверждай вместо Кирилла: дай варианты и рекомендацию по маршруту решений Governance. Claude самостоятельно выбирает реализацию, файлы, порядок работы и адресные проверки внутри разрешённого объёма. Точный технический способ предписывай только при подтверждённом контракте, выявленном дефекте или существенном риске.
2. Запускай установленный `C:\Users\523ur\.local\bin\claude.exe` из каталога репозиториев с `--model opus --strict-mcp-config` и проверяй, что выбран Claude Opus 5.5, а список MCP-серверов пуст. Для анализа используй `-p --permission-mode plan`; для прямо разрешённой разработки — `-p --permission-mode auto`. Добавь `--output-format stream-json --verbose` и сохрани stdout в локальный файл под входным каталогом `.tmp`, stderr отдельно. Передай содержимое UTF-8 файла как один аргумент. Это отдельный сеанс Claude Code, а не уже открытое окно Claude Desktop.
3. С Claude общайся только через терминал и CLI, без MCP. Если для порученной работы нужны YouTrack, GitHub или TEST, запускай процесс через разрешённый `exec_command` с `require_escalated` от пользователя этого ПК: изолированный процесс ранее не мог обращаться к YouTrack и читать нужный SSH-ключ. Не копируй ключи или токены, не отключай проверку SSH host key и не используй `bypassPermissions`. Если требуется только локальное чтение, повышенный запуск не нужен. Проверяй реальный результат доступа, а не путь к файлу.
4. При каждом запуске Claude используй локальное окно диалога на `127.0.0.1:8770` по разделу ниже. Поручи Claude самостоятельно обновлять `.tmp/claude-status.json` при начале работы и на контрольных точках. В потоковом JSON не публикуй внутренние размышления, содержимое секретных файлов или сырой лог. Между контрольными точками не следи за каждым действием Claude, не диктуй последовательность внутренних шагов и не опрашивай Git или YouTrack. Проверяй готовый diff и отзыв ревьюера, коммиты, push и TEST после его явного отчёта о соответствующем этапе; при сбое или запросе решения вмешайся сразу. Владельцу сообщай о существенном прогрессе, проблеме и результате.
5. При паузе пользователя прерви именно запущенный сеанс Claude, проверь, что процесс завершился, зафиксируй номер задачи, Git-состояние и последний подтверждённый этап. При возобновлении перечитай живое состояние; не повторяй уже совершённые внешние записи. Статус задачи и SHA сохраняй в YouTrack/Governance, а устойчивые правила — в Claude `CLAUDE.md` и его проектной памяти.

## Локальное окно Claude

Отдельный статус-сервер `tools/claude-status/server.cjs` на `127.0.0.1:8769` оставь доступным при необходимости, но не открывай его вместо окна диалога. При `Start-Process` используй `-WindowStyle Hidden`. Этапы в `.tmp/claude-status.json` называй кратко: «Анализ задания», «Пишу код», «Ревью», «Тест», «Исправления», «Публикация», «Выкладка», «Пауза», «Готово»; конкретное поручение владельца может исключать некоторые этапы. Ставь `claudeWorking: true` на время активного этапа Claude и `false` при завершении, паузе или работе разработчика-координатора. Не публикуй локальные серверы в сеть и не переноси в них токены.

В поручении Claude укажи, что он обновляет `phase`, `summary`, `updatedAt`, `milestones` и `runLog` в `.tmp/claude-status.json` при старте и после каждого существенного этапа: подготовка решения, завершение кода, собственное отдельное ревью, готовность к независимому ревью Codex, локальные коммиты, публикация в `test`, выкладка TEST, блокер или завершение. `summary` пиши коротко и без секретов. Codex сверяет факты в Git, YouTrack и живой среде только после отчёта Claude о соответствующей контрольной точке. Если окно недоступно, восстанови локальный сервер; постоянный опрос Claude этим не заменяй.

Постоянный выбранный владельцем вид — сообщения с Claude в боковой панели: запусти локальный `tools/claude-status/dialog.cjs` на `127.0.0.1:8770` и открой страницу в видимом браузере Codex. Если окно уже открыто и сервер работает, используй его повторно. Перед запуском укажи в `.tmp/claude-status.json` абсолютные пути `runLog` и `promptFile` к текущим файлам под `.tmp`. Статус в правом верхнем углу: «Ждёт указаний» при `claudeWorking=false`, «Работает» при `claudeWorking=true`, «Ждёт ответ» при `awaitingReply=true` или соответствующем этапе, «Не подключен» при недоступном локальном источнике. При блокере, требующем ответа, установи `awaitingReply=true`; при продолжении сбрось в `false`. Эта страница показывает точный текст поручения и ответы Claude из потокового журнала с безопасным оформлением Markdown (выделение, списки, ссылки и блоки кода), но не служебные события, вызовы инструментов и внутренние рассуждения. После смены задачи проверь, что окно читает новый журнал. Обновление страницы читает только локальные файлы и само по себе не делает запросов к Claude и не расходует лимит подписки. Это просмотр диалога, а не интерактивный терминал Claude. В поручениях Claude говори естественным языком без имени владельца; не упоминай Codex, LLM или автоматическую передачу задач, если это не требуется для самой задачи.

После завершённого ответа Claude локальный сервер сам запускает отдельный сеанс официального Codex CLI, без действия владельца. Кнопка «Позвать Codex» служит ручным запасным запуском и показывает состояние сеанса. Сервер передаёт текущий статус и путь к журналу автоматически; вставлять текст в чат не требуется. Повторный запуск для одного завершённого этапа блокируется. Это отдельный сеанс Codex, не продолжение данного чата; итог и диагностические журналы остаются в `.tmp/codex-summon-*`. При ошибке запуска разбери причину по локальному журналу, не показывая секреты. Веб-страница доступна только на `127.0.0.1` и не должна принимать произвольную команду или текст поручения из HTTP-запроса. Сам запуск Codex не даёт новых полномочий на push, миграции или выкладку; применяй обычные правила Governance.

## Граница сдачи

### Режим очереди задач разработчика-координатора с 29.09.2026

Владелец поручения разрешил для следующих задач этой очереди сократить проверки: Claude реализует и делает самопроверку, Codex один раз коротко просматривает итоговый diff и критические риски, затем после его одобрения коммиты сразу публикуются в `test`. Запускай только адресные проверки, без которых нельзя безопасно судить о деньгах, правах, миграции или совместимости; остальные тесты и повторные циклы ревью не добавляй по привычке. В отчёте явно укажи, что не запускалось. Это решение о порядке данной очереди; если требование Governance о двух отдельных циклах или проверке главным по технике относится к конкретному изменению, зафиксируй расхождение и выполни обязательную проверку либо получи предметное решение уполномоченного человека. Не выдавай короткий просмотр за два независимых ревью.

Для этой очереди push в `test` следует за короткой проверкой каждого готового кандидата. Общий TEST разворачивается одним согласованным пакетом после завершения всех выбранных задач; перед ним всё равно нужны точные SHA, проверка цепи миграций, резервная копия и план отката. Отдельный push не означает выкладку.

Codex выступает архитектором: разбирает задачи, формулирует конкретное ТЗ, делает простые фичи, проводит короткое независимое ревью и явно одобряет публикацию точных SHA. Claude разрабатывает сложные фичи и исправления. По умолчанию первый независимый цикл ревью проводит отдельная сессия Claude, не автор; для этой очереди действует уточнение выше. Тесты, lint, typecheck, build и ручные функциональные проверки запускают только в заранее согласованном владельцем объёме; без разрешения фиксируют непрогон. После применимых циклов ревью и обязательной человеческой проверки Claude отправляет коммиты в Git только после явного одобрения Codex. Выкладку TEST или production Claude выполняет только по отдельному указанию Codex, основанному на разрешении владельца для данной среды и кандидата; production дополнительно требует утверждения Кирилла по Governance. Перед выкладкой сверяют SHA, миграции, план отката и живую среду. Ветка `test` и работающий TEST — разные состояния.
