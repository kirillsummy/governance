# Координация Claude Code

Применяй навык, когда владелец поручает работу Claude или спрашивает о переданной задаче. Прочитай [устав](../../../CHARTER.md), [порядок работы](../../WORKFLOW.md) и инструкции затронутых репозиториев. На рабочем ПК Юры конкретный запуск и доступ описывает локальный `skills/claude-summy/SKILL.md` в каталоге чатов SUMMY; проверь наличие файла и средств запуска, не считай этот путь переносимым на другой хост.

Перед новой передачей сверь задачу YouTrack, Git-состояние и уже работающий сеанс Claude. Сохрани чужую работу. Дай Claude конкретные требования, критерии приёмки, границы публикации и среды, а также решение владельца о тестах по [политике проверок](../../RESTRICTIONS.md#проверки). Не расширяй поручение из-за роли Claude. Отдельный сеанс Claude Code не является открытым окном Claude Desktop.

Перед запуском Claude открой владельцу локальное окно статуса. На ПК Юры точка входа — `tools/claude-status/server.cjs` в каталоге чатов SUMMY; переносимый код окна приложен к этому навыку в [scripts/claude-status-server.cjs](scripts/claude-status-server.cjs). Приложение принимает путь к локальному каталогу статуса аргументом, слушает только `127.0.0.1:8769` и читает `.tmp/claude-status.json`. Оно показывает задачу, текущий этап, короткое описание, контрольные точки и время обновления. Называй этап кратко: «Анализ задания», «Пишу код», «Ревью», «Тест», «Исправления», «Публикация», «Выкладка», «Пауза», «Готово». Блок последних действий, сырой журнал, команды, секреты и внутренние размышления не показывай. Страница получает обновление только после записи новой контрольной точки в `.tmp/claude-status.json`, без периодического опроса. Поле `claudeWorking: true` включает индикатор у статуса во время активного этапа Claude; при завершении, паузе или работе Codex ставь `false`. Не публикуй локальный сервер в сеть. На другом хосте настрой местную точку входа и путь без переноса ключей, токенов и логов.

Поручи Claude обновлять краткий статус при начале работы и после завершения кода, ревью, коммита, push, выкладки, блокера и сдачи. Между контрольными точками Codex не следит за каждой командой и не опрашивает Git или YouTrack. После явного отчёта Claude независимо проверь diff, задачу, опубликованные SHA и среду в пределах разрешённых проверок. Владельцу сообщай существенные этапы, не публикуя сырой лог. Отчёт Claude сам по себе не доказывает push, TEST или production. Автор не проводит независимое ревью собственного изменения; соблюдай циклы ревью из устава.

При просьбе остановить работу прерви именно порученный сеанс Claude, проверь завершение процесса и сохрани подтверждённый этап. При возобновлении заново сверь живое состояние и не повторяй внешние записи вслепую. Публикация, миграция и выкладка требуют своих полномочий и условий; разделяй локальный код, Git, TEST и production в итоговом статусе.
