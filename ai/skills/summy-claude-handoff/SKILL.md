# Координация Claude Code

Роли Codex и Claude, приёмка и отчёт — в [уставе](../../../CHARTER.md#роли-и-ответственность),
процедура — в [порядке работы](../../WORKFLOW.md#координация-codex-и-claude).
Здесь — способ запуска и наблюдения, переносимый на любой ПК.

## Передача

1. Сверь задачу YouTrack, Git-состояние затронутых репозиториев и уже
   работающий сеанс Claude; чужую работу сохрани.
2. Поручение — UTF-8 файл по [шаблону](../../../templates/kickoff.md): задача,
   результат, критерии готовности, существенные ограничения. Без предыстории,
   объяснения ролей и пересказа постоянных правил. Имя владельца поручения в
   поручениях, статусах и сообщениях не упоминай.
3. Запускай официальный неизменённый Claude Code CLI из каталога
   репозиториев SUMMY без MCP-серверов (`--strict-mcp-config`), с моделью
   `opus`, `--effort high` и `--permission-mode auto`, без обхода разрешений.
   Управляемый запуск, принимающий уточнения из окна, —
   `node scripts/claude-managed-runner.cjs --root <каталог-чатов> --run <имя>
   --session-id <uuid> | --resume <uuid> --prompt-file <.tmp/поручение.txt>
   --claude <путь CLI> --cwd <каталог репозиториев>`: он держит stdin CLI в
   формате `--input-format stream-json` с `--replay-user-messages`, пишет
   журнал в `.tmp/<имя>.jsonl`, stderr, `.launch.json` и
   `.runner-result.json`. Прежний запуск `-p` с поручением аргументом тоже
   допустим, но уточнения во время такого запуска не принимает. Токены,
   cookies и файлы сессий не извлекай и не передавай.
4. Запиши в `.tmp/claude-status.json` поля `task`, `phase`, `summary`,
   `updatedAt`, `milestones`, `claudeWorking`, `awaitingReply` и абсолютные
   пути `runLog`, `promptFile` под `.tmp`. Claude обновляет статус на
   контрольных точках: код, публикация, выкладка, блокер, завершение.

## Окно: наблюдение и уточнения

Локальное окно — `node scripts/dialog.cjs <каталог-чатов> [--config <файл>]`
на `127.0.0.1:8770`; в конфиге — `port`, путь CLI (`claude`) и каталог
репозиториев (`cwd`), без секретов. Окно не публикуется в сеть и не создаёт
сессий Codex.

- **Список потоков** — последний запуск каждой `sessionId` из всех
  `.tmp/*.launch.json` и реестров `.tmp/claude-dispatch-*.json`; id потока —
  сама `sessionId`, выбор не сбрасывается при обновлении и хранится отдельно
  для каждой вкладки (`sessionStorage`, ключ v2; прежний общий ключ
  `localStorage` только однократно читается при первой загрузке вкладки),
  поэтому другие и старые вкладки его не меняют. Название потока —
  последнее непустое название задачи (`task` запуска или его статус-файла)
  среди запусков этой `sessionId`; продолжение из окна получает его через
  `--task`, поэтому техническое имя запуска названием не становится. Состояние берётся
  из `.runner-result.json` и живого процесса запуска (PID, время создания и
  командная строка); metadata и статус-файл работу не доказывают. Окно
  показывает время обновления и ошибки связи; непроверяемый владелец
  процесса — «Состояние не проверено».
- **Журнал** — поручение и ответы Claude с безопасным Markdown, уточнения
  отдельной ролью, без служебных событий и рассуждений. Журналы в UTF-8 и
  UTF-16LE (перенаправление PowerShell) читаются.
- **Уточнение** — поле внизу, «Отправить» (Enter; Shift+Enter — новая
  строка). Отправка только явным действием, идентификатор уточнения
  создаётся на странице: повтор, перезагрузка, двойное нажатие и перезапуск
  окна дубля не создают; неподтверждённый черновик хранится на странице до
  ответа сервера отдельно для своего потока. Уточнение привязывается к
  потоку, выбранному в момент отправки; при переключении черновик не
  переносится. Состояния: в очереди → передано в CLI → получено
  (квитанция CLI — эхо того же `uuid` через `--replay-user-messages`; CLI
  отдаёт его, когда берёт сообщение в ход) → отвечено (результат с этим
  `uuid` в `user_message_uuids`, иначе — результат сразу после эха);
  «не доставлено» — с причиной, ход с ошибкой так и показан. Запись файла
  или очередь получением не называются. Управляемый запуск закрывает stdin
  через 20 с простоя после результата, когда неотвеченных ходов нет.
  - Работающий управляемый запуск — уточнение сразу уходит в его stdin; CLI
    берёт его после текущего хода.
  - Работающий прежний запуск `-p` — stdin нет: процесс не прерывается,
    конкурентный `--resume` не запускается, уточнение ждёт в устойчивой
    очереди и после завершения запуска продолжает ту же сессию новым
    управляемым запуском `--resume`.
  - Свободная сессия — продолжение тем же способом сразу.
  - Владелец процесса не проверен — ожидание с причиной.
- **Очередь** — `.tmp/claude-dialog/<sessionId>/messages/<id>.json` и
  `owner.json` каталога чатов; изменения — под межпроцессным мьютексом
  сессии, атомарной записью, переходы состояний только вперёд. Продолжение
  запускается, только если по свежему списку процессов (время снимка — его
  начало) нет живого запуска этой сессии, только что начатого запуска и
  процесса CLI с её `sessionId` или с нечитаемой командной строкой; runner
  перед стартом CLI проверяет то же сам. Владелец управляемого запуска
  считается завершённым только после двух снимков без него; посторонние
  процессы не трогаются.
- **Защита** — только loopback, проверка `Host` и `Origin`, ключ страницы
  в заголовке `X-Dialog-Token`, JSON до 32 КБ в строгом UTF-8, известная
  `sessionId`, текст до 8000 символов без управляющих символов, без путей,
  команд и PID из запроса; CLI запускается списком аргументов без оболочки;
  CSP без внешних источников, текст выводится через `textContent` или
  экранированный Markdown.
- **Проверки окна** — `node --test scripts/tests/dialog.test.cjs
  scripts/tests/client.test.cjs` (фальшивый CLI `tests/fake-claude.cjs`;
  клиент — в двух вкладках с отдельными хранилищами); продуктовые тесты к окну не
  относятся. Реальная проверка доставки — только отдельной проверочной
  сессией без инструментов (`--no-tools`), не продуктовыми сессиями.

Панель статуса `scripts/claude-status-server.cjs` на `127.0.0.1:8769` —
дополнительная, не вместо диалога.

Между контрольными точками за каждой командой не следят. Результат
возвращается исходному чату Codex: он читает отчёт Claude, журнал CLI-сеанса
и сверяет факты — поручение, опубликованные SHA, результат развёртывания,
YouTrack и Governance. Отчёт Claude сам по себе выкладку не доказывает.

## Остановка и возобновление

При остановке прерви только порученный процесс Claude, проверь его
завершение и зафиксируй подтверждённый этап. При возобновлении сверь Git,
YouTrack и среду; внешние записи вслепую не повторяй.

Локальные копии этого окна и инструкций на рабочем ПК содержат только ссылки
на канон и особенности машины; пути и учётки ПК в Governance не публикуются.
