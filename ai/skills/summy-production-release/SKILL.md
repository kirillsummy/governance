# Выпуск SUMMY в production

Сначала прочитай [текущее состояние](../../../docs/current-state.md), [релизный порядок](../../../CHARTER.md#релиз-процесс-стандарт), [ветки](../../../docs/branches.md) и [инфраструктуру](../../../docs/infrastructure.md#production-по-конфигурации). Каждая production-выкладка требует отдельного явного утверждения точного кандидата по [уставу](../../../CHARTER.md#релиз-процесс-стандарт); без него не меняй production-ветки, теги, сервер и БД, подготовка кандидата сама по себе разрешения не даёт.

Состав кандидата бери из release-карточки, куда по точным SHA переданы TEST-составы сводных карточек ([доска](../../../CHARTER.md#доска-youtrack-сводные-карточки-категорий)); переход сводной в «На тесте» сам по себе кандидата не утверждает. Для кандидата перечисли по каждому продукту полный SHA, сборку, включённые и исключённые функции, флаги, миграции «с → на», зависимости читателей и план восстановления. Тесты кандидата проводятся до выкладки, их результаты записываются; не прошедший проверки кандидат не выкладывается. Сверь удалённые refs и фактические версии production раздельно; ветка, тег, YouTrack и датированный отчёт не заменяют живую проверку. Production-БД Timeweb управляется отдельно от сервера приложений: права, endpoint и резервные копии подтверждай для нужной среды, не переноси реквизиты TEST.

Перед выполнением нужен утверждённый Кириллом точный кандидат по [уставу](../../../CHARTER.md#релиз-процесс-стандарт) и действующее право доступа. Повторно сверь состав с утверждением, миграции, совместимость, восстановимые копии, место на диске и способ отката. Дополнительные права, секреты, платежи и необратимые операции требуют своих решений. При расхождении состава или условий остановись до переключения.

Поставляй только утверждённые SHA по актуальным продуктовым runbook; не считай исторический пример команды универсальным. После переключения проверь работающие версии, ревизию БД и доступность сервисов. Пользовательские сценарии и проверки кода выполняй в объёме поручения и [политики проверок](../../RESTRICTIONS.md#проверки); непрогон указывай явно. При сбое применяй заранее согласованный откат, не считай downgrade схемы безопасным по умолчанию.

Запиши фактические SHA, миграции, проверки и ограничения в релизный отчёт, CHANGELOG и нужные задачи YouTrack; метки выпуска ставь по релизному порядку. Отделяй подготовленный кандидат, опубликованную production-ветку и реально работающий production.
