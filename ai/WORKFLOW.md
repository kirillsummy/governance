# Порядок работы агента

1. Прочитай [ограничения](RESTRICTIONS.md), [состояние](../docs/current-state.md),
   раздел [архитектуры](../docs/architecture/README.md) выбранного продукта и его AGENTS/DEBT.
2. Проверь Git root, remote, production/`test`/`work`/`singular`, upstream и dirty-state; выясни, где живёт факт,
   который меняешь. Для стыка перечисли API/DTO/BFF/витрины и потребителей.
3. Выполни согласованную задачу. Читай код точечно; неизвестное помечай,
   существующие запреты не расширяй собственными догадками.
4. Запускай автоматические тесты только по прямой просьбе разработчика. Обнови один канонический
   документ, а в остальных местах поставь ссылку; сохрани историю уникального решения.
5. Обычную работу веди в `work`, созданной от актуальной `test`. Коммит, CHANGELOG,
   передача с точным SHA и границами проверки; production и `test` не меняй
   без прямого указания разработчика.
   `singular` используй только как архив достижимости исключительных SHA; не веди
   в ней обычную работу и не мержи её целиком в рабочие или выпускные ветки.
   Для Governance временная ветка после включения в main не остаётся постоянной.

[Skills](skills/README.md) помогают выполнять повторяемые задачи. Они не обязательны
для каждого изменения и не включают автономный мониторинг/рассылку/деплой.
Шаблоны: [задание](../templates/kickoff.md), [передача](../templates/handoff.md).
