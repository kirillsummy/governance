# Внешние аккаунты мастера и общее расписание

Ответ пользователя 03.10.2026 (SUM-97 Q24-9): DIKIDI и Авито — источники знаний
для мастеров и CRM; мастер сам привязывает свои аккаунты в настройках профиля,
чтобы видеть всё расписание в одном месте. Реализация 04.10.2026: backend `e76d6ff0c05c518d7efb11d6984d2f3e56b6c748`
(миграция `0187_master_external_accounts`), master-app `6b8b0e1ba46c32f22d41cd09f7c63f76625def77`.

## Граница

- `/v1/master/external-accounts` — только сессия мастера (`internal_master_id`):
  список провайдеров с причиной недоступности, привязка (`provider`,
  `account_ref`, подпись), отвязка `POST /{id}/unlink` — строка остаётся
  (`state=unlinked`). Один внешний аккаунт привязан не больше чем к одному
  мастеру (409 `external_account_taken`); идентичности не смешиваются.
- Секреты и ключи не принимаются и не хранятся; приём ключа появится вместе с
  адаптером, сверенным по официальной документации. Права CRM на личные данные
  мастера не расширяются.
- `/v1/master/schedule-aggregate` — дни из расписания SUMMY (YClients) с меткой
  источника и состояние каждого привязанного аккаунта: `unavailable`, время
  обновления, ошибка или причина. Записи DIKIDI, Авито и YClients не меняются.
- master-app: «Настройки → Подключения», «Общее расписание»
  (`/profile/schedule-all/`).

## Не решено

DIKIDI: ключ «Доступ к API» выдаёт компания в DIKIDI Business, публичной
документации методов расписания нет — чтение не подключено. Авито: календарь
бронирований есть только у посуточной аренды, для услуг его нет. Реальные
аккаунты добавляют мастера сами.
