# Контракт: отзывы клиентов о мастере

Читают: бэкенд (зеркалит из YClients, считает, отдаёт), сайт (число, оценка и
тексты на странице мастера), приложение мастера (мастер видит свои отзывы),
CRM (рычаг снятия). Пишется здесь; меняется первым — затем стороны,
отдельными ветками.

Основание: слово владельца 07.09.2026 (через релиз-инженера): «подключай
реальные отзывы с текстами»; ранее 28–29.08.2026: «отзывы по мастеру надо
взять из yclients пока», «не писать yclients», «у кого 0.00 — так и ставь и
0 отзывов». Разведка релиз-инженера 07.09.2026 (живое чтение боя, только
чтение): единственная рабочая ручка — `GET /api/v1/comments/{company_id}`
(`count`, `page`; «логичные» пути `company/{id}/reviews`, `reviews/{id}`,
`staff/{id}/comments` — 404); поля `id, salon_id, type, master_id, record_id,
rating, text, date, user_id, user_name, user_avatar, user_email, user_phone`;
у двенадцати мастеров сайта 503 отзыва, 322 с текстом; средние по ним
совпадают до сотой с `staff_members.rating` — рейтинг, который мы зеркалим,
и есть среднее по этим отзывам; у одного мастера ноль отзывов — это правда,
а не сбой.

## Одна дверь

Сайт и приложение в YClients напрямую не ходят: отзывы **зеркалятся в
платформу** заданием синка, как записи, и отдаются своими ручками. Причина
та же, что у всего зеркала: одна дверь, один ключ, витрина переживает уход
от YClients.

## Что храним

Таблица отзывов, одна строка на отзыв YClients, ключ — `(company_id,
external_id)`; связь с мастером — через `external_refs` (`staff`), с записью —
через зеркало записей, если она есть.

    external_id, company_id, staff_id, visit (если нашли), rating (1–5),
    text (может быть пустым), created_at (дата отзыва), type (как пришёл),
    author_name — отображаемое имя автора как в источнике,
    hidden_at / hidden_by / hidden_reason — рычаг снятия, либо пусто,
    synced_at, deleted_at (пропал из источника — помечаем, не стираем)

⛔ **Телефон, почта и аватар автора не хранятся и не отдаются никому** — это
персональные данные клиента, витрине они не нужны (как со СНИЛС в
медкнижке: захотим хранить — отдельное решение владельца).

**Счётчик и среднее считает платформа** по живым нескрытым отзывам: число —
все отзывы, включая без текста; среднее — по всем оценкам. Ноль отзывов —
`0` и `null`, не «Демо» и не придуманное число.

## Что видит сайт

`GET /v1/public/masters/{staff_id}` — к `rating` добавляются
`reviews_count` (всего) и `reviews_with_text` (с текстом).

`GET /v1/public/masters/{staff_id}/reviews?limit&offset` — только отзывы **с
текстом**, свежие сверху, страницей общего вида:

    id, rating, text, created_at, author_name

Автор показывается **первым словом имени** из источника (решение по
умолчанию, слово владельца может изменить); ссылок на автора, аватара, записи
и услуги нет.

## Что видит мастер

`GET /v1/profile/reviews?limit&offset` — свои отзывы, те же поля плюс
`hidden_at` (мастер видит, что снято, и не гадает, куда делся отзыв).
Профиль (`/v1/profile`) отдаёт `reviews_count` и `rating` для шапки.

## Рычаг снятия — не модерация

Показываем **все** нескрытые отзывы, включая низкие оценки (решение по
умолчанию, слово владельца может изменить). Снять отдельный отзыв с показа
может служебная сторона — `POST /v1/admin/reviews/{id}/hide?reason=…` —
актор и причина обязательны, след в аудите; снятый отзыв **остаётся в
счётчике и среднем**: оценка была поставлена, скрыт только текст с витрины.
Возврат — `POST …/unhide`. Очереди на проверку нет, публикация зеркала
мгновенная.

## Синк

Задание синка по расписанию (как записи): постранично `comments/{company_id}`
до пустой страницы для каждой компании сети; новые — вставка, изменённые —
обновление, пропавшие — `deleted_at`; итог — в `sync_runs`, не в логе; маячок
`/v1/freshness` получает класс `reviews`. Первый накат на бою — обычным
циклом синка, импортёр руками не зовём.

## Чего этот контракт не покрывает

- **Ответы мастера/салона на отзывы** — в источнике их нет.
- **Отзывы о студии в целом** (Яндекс, 2ГИС) — свой контент сайта, здесь не
  смешиваются.
- **Разметку Review/AggregateRating** на сайте — правило SEO-аудита сайта
  (Review-разметку не делаем), решается там.
- **Назначение поля `type`** — хранится как пришло, толкование после замера
  на первом накате (в хендоффе — распределение значений).
- **Согласие клиента**: отзыв написан для публичного показа в YClients, имя
  показываем как там; иное — вопрос владельца.
