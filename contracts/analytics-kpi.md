Прямое поручение владельца 04.10.2026 (через разработчика-координатора):
изучить публичные материалы KPI.bi и перенести полезные отсутствующие методы и
визуализации в CRM на данных SUMMY, не дублируя готовые «Возвращаемость» и RFM
([analytics-overview](analytics-overview.md)). Код — backend
`8802e27e2360692d1daea4c806424703b71a885d` (`app/domains/analytics/kpi.py`,
миграция `0194_client_care_tasks`), CRM `14f02e90669ee9f0a45d00cad040d69501763279`
(«Аналитика → Показатели KPI» `/analytics/kpi`, «Клиенты → С кем связаться»
`/clients/kdo`, до 06.10.2026 — «КДО»).
Dev — `dak2-dev-20261004`. Ответ на вопрос № 37 SUM-96 в части показателей.

## Общие правила

- Считает только backend (`/v1/analytics/kpi/*`); браузер не получает клиентскую
  базу для расчёта. Каждый ответ несёт `definitions` (числитель, знаменатель,
  правило), период, прошлый период той же длины (где есть сравнение), время
  расчёта, свежесть синка и причины неполноты; неизвестное и неполное — не ноль.
- Часовой пояс — платформы (`platform_timezone`), период включает обе даты, будущие
  записи не входят. Факт визита — запись `arrived` или `completed` (как в «Цикле
  клиентов»). Фильтры филиала, мастера (мастер позиции, иначе записи) и услуги —
  общие для всех отчётов.
- Права: отчёты — раздел «Аналитика» (`require_analytics_viewer`); исходные записи
  (`/facts`) и КДО (`/kdo`, `/kdo/tasks`) — дополнительно «Клиенты»
  (`require_analytics_clients_viewer`), запись задач в CRM — по праву правки
  «Клиенты».
- Деньги — только «подтверждённые оплаты по источнику»: сумма позиций
  (`final_amount`) состоявшихся записей с последним снимком YClients `paid_full`.
  Это не бухгалтерская выручка и не прибыль; новых финансовых, бонусных и
  налоговых правил нет.

## Методы

| Метод | Формула и знаменатель | Ручка |
|---|---|---|
| День недели × час | визиты и уникальные клиенты по часу начала; занятые минуты — объединённые интервалы позиций по сотруднику; доступные — объединённые интервалы `staff_schedules`; доля = занятые / доступные только при доступных > 0; визиты в дни без графика — отдельный счётчик | `heatmap` |
| Сравнение и доходимость | по филиалам, мастерам, услугам, месяцам: записи (id один раз; перенос — та же запись), состоявшиеся, отмены, неявки, без отметки; доходимость = состоявшиеся / все прошедшие записи охвата; уникальные и повторные клиенты; оплаты; прошлый период; недельная динамика | `compare` |
| Возвратность по базе 240 дней | база — уникальные клиенты с визитом за N дней до начала периода (240 по умолчанию, 30–730); вернувшиеся — клиенты базы с визитом в периоде; новые для базы — отдельно; помесячно; граница истории зеркала | `return-240` |
| ОПЗ | клиенты, кому в день состоявшегося визита создана будущая запись (`source_created_at`) / клиенты с визитом в периоде; судьба созданных записей; покрытие даты создания; по мастеру визита | `opz` |
| Воронка | первое входящее сообщение клиента в журнале (только диалоги с явной привязкой) → первая запись, созданная в окне N дней (7 по умолчанию) → визит → подтверждённая оплата; наблюдение, не причинность; без привязок — «Функция в разработке» | `funnel` |
| Ассортимент | категорий услуг на клиента, распределение, спрос услуг, мультиуслужные визиты; товары в зеркале не хранятся | `assortment` |
| Каскад (waterfall) | вклад строки = подтверждённые оплаты текущего периода − прошлого; сумма вкладов точно равна изменению итога | `factors` |
| КДО («С кем связаться») | сегменты из фактов: отмены и неявки без будущей записи (14 дней), контроль качества (визит за 3 дня), «пора» и «пропал» по порогам «Цикла клиентов», длительный риск (180–730 дней без визита и без будущей записи), ближайшая ОПЗ (визит за 7 дней без будущей записи), дни рождения (14 дней, визит за год); пороги в ответе; лист ожидания — «Функция в разработке» | `kdo` |

Задачи КДО (`client_care_tasks`, история `client_care_task_events` append-only,
повтор по `request_id` не дублирует): ответственный, срок, состояние (`open`,
`in_progress`, `done`, `dismissed`), следующий шаг, результат; «сделано» требует
результата. Сообщения клиентам не отправляются; риск и просрочка не означают ухода.

## Интерфейс CRM: назначение экранов (SUM-220 п. 34, 37, 06.10.2026)

- Экран задач КДО в CRM называется «С кем связаться» — во вкладке клиентов,
  заголовке, возврате из карточки клиента, крошках и заголовке вкладки браузера
  (CRM `362bd0d8`, `0f6b517b`). Адрес `/clients/kdo`, сегменты, задачи и права
  прежние.
- Под переключателем «Показателей KPI» — одна строка, на какой вопрос отвечает
  выбранная вкладка; «План/факт» и «Абонементы» в ней прямо названы неготовыми.
  Выбранная вкладка хранится в `?tab=` (CRM `4dddd481`). Формулы, разрезы и
  права не менялись. Заголовок вкладки браузера у всех вкладок общий:
  заголовок считается по пути без `?tab=`.
- «Воронка» KPI — аналитический путь «сообщение → запись → визит → оплата», а
  «Цикл клиентов» — вычисленные статусы по порогам отсутствия. Ни то, ни другое
  не канбан работы с клиентом. Клиентский канбан со стадиями (SUM-220 п. 36) не
  реализован: стадии и переходы не утверждены, вопрос владельцу.
- «Клиенты → Сводка»: «Частые вопросы» ведут туда, где ответ уже считается.
  Повторные у мастера — таблица мастеров, выпавшие по услуге — «Цикл клиентов»
  (порог в `?threshold=`), «С кем связаться», «Возвращаемость». Пункт показан
  только при доступе к разделу (CRM `f65bda5e`, `bb5677a2`).
- Доставка: CRM `a071b40` на Dev (`sfx7-dev-20261006`); заголовок `0f6b517b` — в
  `test` `812e860`; выкладка на Dev не подтверждена (по журналу доставок
  06.10.2026 18:01 на Dev CRM `41c6b8d`).

## Чего нет и почему

- Закрытая формула индекса мастера KPI.bi (MInd) не воспроизводится — показаны
  открытые составляющие с динамикой; рыночные нормативы и «максимумы» не
  используются.
- План/факт — планов в SUMMY нет, источник плановых значений не утверждён:
  интерфейс «Функция в разработке» с перечнем допустимых показателей.
- Абонементы — интеграция не читает абонементы YClients (`prepaid.py`,
  `not_connected`): интерфейс «Функция в разработке», цифр нет.
- Календарь записей не принимает фильтр из ссылки — ячейка ведёт к исходным
  записям в окне и общей ссылке на календарь.
- История переносов записей в зеркале не хранится: перенесённая запись видна с
  последней датой.
- Проверки: миграция `0194` — upgrade → downgrade → upgrade на одноразовой
  PostgreSQL 18 и применена на Dev; SQL отчётов до Dev не исполнялся, тесты и
  сценарии не проводились.
