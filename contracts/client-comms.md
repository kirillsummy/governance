# Переписки с клиентами: центр общения CRM (P19/P20, SUM-127)

Решение D13 ([технические решения 03.10.2026](../docs/decisions/2026-10-03-technical-decisions-d01-d13.md)):
сервис переписок — Chatwoot, окно — своё в CRM, связь — только через backend по
Application API. Реализация 03.10.2026: backend `docs/comms.md`, CRM «Клиенты →
Общение» (`/clients/chats`).

## Граница

- Браузер CRM не получает адрес и токен Chatwoot. Ручки backend `GET /v1/comms/state`,
  `GET /v1/comms/conversations`, `GET /v1/comms/conversations/{id}/messages` —
  под сервисным токеном и CRM-сессией с правом раздела «Клиенты».
- Настройка `CHATWOOT_URL`, `CHATWOOT_ACCOUNT_ID`, `CHATWOOT_API_TOKEN` — только
  серверный runtime. Без неё состояние `configured=false`, чтение диалогов — 503
  `comms_not_configured`; экран показывает «Функция в разработке» и причину,
  пустой список не подставляется. Сбой Chatwoot — 503 `comms_unavailable`.
- Отправка, назначение ответственного и смена статуса диалога не включены:
  `send_available` всегда `false`, кнопки CRM отключены и подписаны. Черновик
  ответа живёт только на открытой странице.
- Контакт Chatwoot не сопоставляется с клиентом SUMMY автоматически: CRM
  открывает поиск клиента по телефону или почте контакта по нажатию.
- Каналы Telegram, MAX, WhatsApp, ВКонтакте, Авито, чат сайта показываются
  подключёнными только если в Chatwoot есть соответствующий входящий ящик.
  Telegram подключается ботом; личный аккаунт, VK и MAX не подтверждены.
- Прежняя квитанция `queued_mock` адаптера каналов CRM удалена: отправка из
  CRM отвечает отказом `comms_send_disabled`.
- Прямые каналы первого этапа — Telegram, MAX, Авито (решение 03.10.2026,
  SUM-97 Q24-11; R136). С 04.10.2026 (backend `eec0ca5`, CRM `93dab1e`)
  `GET /v1/comms/state` отдаёт `direct_channels`: `not_configured` /
  `configured` только по наличию серверных настроек
  (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `MAX_BOT_TOKEN`,
  `MAX_WEBHOOK_SECRET`, `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET`; значения
  не выдаются, «подключён» не показывается). Готов разбор вебхука Telegram
  (секрет `X-Telegram-Bot-Api-Secret-Token`, идемпотентность по
  `update_id`) и сверка секрета MAX (`X-Max-Bot-Api-Secret`). Маршрута
  вебхука, хранения, миграций и отправки нет: они включаются после доступов и
  ответа SUM-96 № 50. Разбор тела сообщения MAX — после сверки полей с
  официальной документацией; Авито — только интерфейс (документация Messenger
  API не прочитана).

## Журнал переписки SUMMY (04.10.2026)

Ответ пользователя 03.10.2026 (SUM-97 Q24-11): работающего сервиса переписки нет,
его реализуют разработчики. Решение Claude: собственный журнал в backend
(`0188_comms_inbox`, backend `e76d6ff0c05c518d7efb11d6984d2f3e56b6c748`), окно — «Клиенты → Общение» (CRM `80efc303dabb208a3ea31c19c693f1c6360e6a3e`).
Chatwoot не развёрнут и штатно не поддерживает MAX и Авито — прежнее чтение
Chatwoot сохранено как необязательный источник и показывается только при
настроенном экземпляре.

- Хранение: диалог на чат канала (`comms_threads`, уникально организация +
  канал + id чата), сообщения с `delivery_state` (`received`, `blocked`,
  `queued`, `sent`, `delivered`, `failed`), метаданные вложений (файл не
  скачивается до правил хранения), `comms_webhook_events` — дедупликация по
  канал + id события, `comms_thread_events` — история назначений (append-only).
- `/v1/comms/inbox/threads` (фильтры статус, канал, мои/без ответственного),
  `/{id}`, `/{id}/read`, `/{id}/assignment` (`take`/`release`; чужой диалог —
  409 `thread_already_assigned`, снять чужое — управляющая и владелец),
  `/{id}/status`, `/{id}/replies` — ответ сохраняется с `blocked` и причиной,
  наружу не уходит. Права — раздел «Клиенты», как у прежнего чтения.
- Вебхуки: CRM `/hooks/comms/telegram|max` пересылает тело и заголовок секрета
  в backend `/v1/comms/webhooks/*`. Telegram — секрет и идемпотентность по
  `update_id`, контакт — подпись чата канала; MAX — только сверка секрета
  (`pending_parser`); Авито — нет. Без ключей канала — 503. Клиент SUMMY
  привязывается только явно (`client_id`), не по имени и телефону.
- `GET /v1/comms/state` дополнительно отдаёт `inbox_available`.

## Не решено

Экземпляр Chatwoot не нужен для журнала (Q24-11 отвечен 03.10.2026); кто отвечает
клиентам вместо администратора, сценарии замены FlowSell, согласия и отписки —
SUM-96 № 50; доступ к серверу коммуникаций (P21) не подтверждён. Реальные
сообщения клиентам не отправлялись.
