# Переписки с клиентами: центр общения CRM (P19/P20, SUM-127)

Решение D13 ([технические решения 03.10.2026](../docs/decisions/2026-10-03-technical-decisions-d01-d13.md)):
сервис переписок — Chatwoot, окно — своё в CRM, связь — только через backend по
Application API. Реализация 03.10.2026: backend `docs/comms.md`, CRM «Клиенты →
Общение» (`/clients/chats`).

## Граница

- Браузер CRM не получает адрес и токен Chatwoot. Ручки backend `GET /v1/comms/state`,
  `GET /v1/comms/conversations`, `GET /v1/comms/conversations/{id}/messages` —
  под сервисным токеном и CRM-сессией с правом раздела «Клиенты».
- Настройка `CHATWOOT_URL`, `CHATWOOT_ACCOUNT_ID`, `CHATWOOT_API_TOKEN` — только
  серверный runtime. Без неё состояние `configured=false`, чтение диалогов — 503
  `comms_not_configured`; экран показывает «Функция в разработке» и причину,
  пустой список не подставляется. Сбой Chatwoot — 503 `comms_unavailable`.
- Отправка, назначение ответственного и смена статуса диалога не включены:
  `send_available` всегда `false`, кнопки CRM отключены и подписаны. Черновик
  ответа живёт только на открытой странице.
- Контакт Chatwoot не сопоставляется с клиентом SUMMY автоматически: CRM
  открывает поиск клиента по телефону или почте контакта по нажатию.
- Каналы Telegram, MAX, WhatsApp, ВКонтакте, Авито, чат сайта показываются
  подключёнными только если в Chatwoot есть соответствующий входящий ящик.
  Telegram подключается ботом; личный аккаунт, VK и MAX не подтверждены.
- Прежняя квитанция `queued_mock` адаптера каналов CRM удалена: отправка из
  CRM отвечает отказом `comms_send_disabled`.
- Прямые каналы первого этапа — Telegram, MAX, Авито (решение 03.10.2026,
  SUM-97 Q24-11; R136). С 04.10.2026 (backend `eec0ca5`, CRM `93dab1e`)
  `GET /v1/comms/state` отдаёт `direct_channels`: `not_configured` /
  `configured` только по наличию серверных настроек
  (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `MAX_BOT_TOKEN`,
  `MAX_WEBHOOK_SECRET`, `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET`; значения
  не выдаются, «подключён» не показывается). Готов разбор вебхука Telegram
  (секрет `X-Telegram-Bot-Api-Secret-Token`, идемпотентность по
  `update_id`) и сверка секрета MAX (`X-Max-Bot-Api-Secret`). Маршрута
  вебхука, хранения, миграций и отправки нет: они включаются после доступов и
  ответа SUM-96 № 50. Разбор тела сообщения MAX — после сверки полей с
  официальной документацией. Авито — читающий адаптер
  `app/domains/comms/avito.py` (backend `61988b0dcca14ec9717e9b891d865447dadfaaea`) по публичному
  экспорту OpenAPI каталога Avito Business API (03.10.2026; официальный портал
  из среды отвечал 429 — сверить до подключения): `POST /token`
  (client_credentials), `GET /core/v1/accounts/self`,
  `GET /messenger/v2/accounts/{user_id}/chats` и `/chats/{chat_id}`,
  `GET /messenger/v3/accounts/{user_id}/chats/{chat_id}/messages/` (не помечает
  чат прочитанным), `GET /messenger/v1/accounts/{user_id}/getVoiceFiles`
  (ссылка живёт час). Отправка, отметка прочтения, удаление, blacklist и
  регистрация вебхука не используются; модуль ни к чему не подключён (backend
  DEBT, пункт 23), канал — «Функция в разработке».

## Журнал переписки SUMMY (04.10.2026)

Ответ пользователя 03.10.2026 (SUM-97 Q24-11): работающего сервиса переписки нет,
его реализуют разработчики. Решение Claude: собственный журнал в backend
(`0188_comms_inbox`, backend `e76d6ff0c05c518d7efb11d6984d2f3e56b6c748`), окно — «Клиенты → Общение» (CRM `80efc303dabb208a3ea31c19c693f1c6360e6a3e`).
Chatwoot не развёрнут и штатно не поддерживает MAX и Авито — прежнее чтение
Chatwoot сохранено как необязательный источник и показывается только при
настроенном экземпляре.

- Хранение: диалог на чат канала (`comms_threads`, уникально организация +
  канал + id чата), сообщения с `delivery_state` (`received`, `blocked`,
  `queued`, `sent`, `delivered`, `failed`), метаданные вложений (файл не
  скачивается до правил хранения), `comms_webhook_events` — дедупликация по
  канал + id события, `comms_thread_events` — история назначений (append-only).
- `/v1/comms/inbox/threads` (фильтры статус, канал, мои/без ответственного),
  `/{id}`, `/{id}/read`, `/{id}/assignment` (`take`/`release`; чужой диалог —
  409 `thread_already_assigned`, снять чужое — управляющая и владелец),
  `/{id}/status`, `/{id}/replies` — ответ сохраняется с `blocked` и причиной,
  наружу не уходит. Права — раздел «Клиенты», как у прежнего чтения.
- Вебхуки: CRM `/hooks/comms/telegram|max` пересылает тело и заголовок секрета
  в backend `/v1/comms/webhooks/*`. Telegram — секрет и идемпотентность по
  `update_id`, контакт — подпись чата канала; MAX — только сверка секрета
  (`pending_parser`); Авито — разбор тела вебхука v3 готов (`parse_webhook`,
  событие для существующего `store_event`), маршрута нет: в публичной схеме
  нет подписи или секрета вебхука, проверка подлинности — решение SUM-97.
  Без ключей канала — 503. Клиент SUMMY
  привязывается только явно (`client_id`), не по имени и телефону.
- `GET /v1/comms/state` дополнительно отдаёт `inbox_available`.

## Перенос истории в журнал (04.10.2026)

Поручение 04.10.2026: перенести чаты действующего FlowSell в SUMMY. Журнал
SUMMY — единственное хранилище; Chatwoot (FlowSell подключает свою запись
Chatwoot) и экспорт Telegram Desktop — источники. Backend `8e9881bb232fcadcb15b50f0b249148e22a3b1e0`
(`0191_comms_import`), `e5fe9bb6bc685819bedd702d63dbce0d0056950b` (`0192_comms_telegram_export`, MAX); CRM
`ace8ea03bf94be80ec0d5637be08256336e978f2`, `9b826e89fe277c7cdf4972898cd1a3c0af53d02e`. Описание полей и ручек — backend `docs/comms.md`.

- Происхождение обязательно: источник, учётная запись (`хост/account_id` для
  Chatwoot, `telegram-desktop`), inbox и тип канала источника, id диалога,
  контакта и сообщения. Повтор не дублирует.
- Канал — только по типу inbox источника; неизвестный — `other`, не Telegram.
  Клиент SUMMY по имени и телефону не сопоставляется.
- Направление: Chatwoot — по `message_type` (0 входящее, 1 и 3 исходящее, 2
  служебное), заметки `private`; экспорт Telegram — исходящими считаются только
  отправители, которых оператор назвал «нашими».
- Вложения скачивает сервер (Chatwoot — только с хоста экземпляра, до 20 МБ;
  Telegram — из архива экспорта) в закрытое хранилище
  `comms/attachments/sha256/<сумма>`; выдача — по праву «Клиенты»,
  `private, no-store`.
- Прогон хранит счётчики сверки и отказы без текста и персональных данных.
  Переносом считается только прогон с реальными записями источника и
  сверенными счётчиками; код и экран сами по себе переносом не являются.
- Источник только читается: в Chatwoot и FlowSell ничего не пишется, каналы не
  отключаются, клиентам ничего не отправляется. Ключи — только серверный
  runtime (`CHATWOOT_URL`, `CHATWOOT_ACCOUNT_ID`, `CHATWOOT_API_TOKEN`); без
  них — «Функция в разработке».
- MAX: вебхук разбирает `message_created` по официальной документации
  (dev.max.ru). Авито Messenger: нормализация для переноса готова (направление
  `in`/`out`, тип сообщения как есть, неизвестный — неизвестен; image и voice —
  вложения, у appCall/file/video контент источник не отдаёт; происхождение
  `api.avito.ru/{user_id}` + id чата). REST отдаёт не дальше offset 1000 без
  total — прогон обязан показывать неполноту. Импорт требует значения
  `source='avito'` (миграция) и доступа.

## Администратор и филиалы диалогов (05.10.2026)

Прямое требование владельца 05.10.2026: администратор видит чаты клиентов и
отвечает. Backend `04ad395383fe3e669381aaf3b97c5c75638edeea` (`0210_comms_thread_locations`),
CRM `cbdcceeebcfab7b8f3c86bf3938659e0ccb4d1b2`.

- Право `client-chats` «Общение с клиентами» — подраздел «Клиентов»: по
  умолчанию владелец, управляющий, администратор; открытые «Клиенты» открывают и
  его. Журнал, история, вложения и ответ проверяются backend: по этому праву
  видны только диалоги своих филиалов (`granted_location_ids`); диалог чужого
  филиала или без филиала отвечает как несуществующий. Владелец и роли с
  разделом «Клиенты» видят все диалоги, как прежде. Поиск, чтение Chatwoot и
  импорт — только раздел «Клиенты».
- Филиал диалога (`comms_threads.location_id`) ставят управляющая (в своих
  филиалах) и владелец; изменение — событие истории `location`.
  Автоматической разметки по каналу нет: соответствие каналов и филиалов не
  утверждено.
- Ответ хранит автора (`author_id`, имя) и время; состояние `blocked` с
  причиной по каналу (нет ключей канала, перенесённая история или правила
  SUM-96 № 50). Наружу ничего не уходит; реальные сообщения не отправлялись.
- CRM: роль без раздела «Клиенты» попадает пунктом меню «Клиенты» сразу в
  «Общение» и видит только журнал.

## Не решено

Экземпляр Chatwoot не нужен для журнала (Q24-11 отвечен 03.10.2026); кто отвечает
клиентам вместо администратора, сценарии замены FlowSell, согласия и отписки —
SUM-96 № 50; доступ к серверу коммуникаций (P21) не подтверждён. Реальные
сообщения клиентам не отправлялись.
