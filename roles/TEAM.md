# Адресная книга команды и правила сообщений

Дополнение к разделу «Как бегут сигналы» устава. Появилось 14.08.2026 после
первого сбоя конвейера: рассылка канона без задачи заставила четыре сессии
крутиться без конца — в сообщениях не было ни стоп-правила, ни адресов.

## Кто есть кто (роль → название сессии)

Адресат ищется ПО НАЗВАНИЮ сессии в списке сессий; номера сессий не канон —
они меняются.

| Роль | Сессия |
|---|---|
| Архитектор-исполнитель | «Архитектор» |
| Дизайн-лид фронтов | «Frontend разработчик» |
| Бэкенд-лид | «Backend разработчик» |
| Тестировщик | «Тестировщик» |
| Эксплуатация | «DevOps-инженер» |
| Владелец | Кирилл — его чат; только деньги/данные и батчи решений |

## Правила сообщений (обязательные)

1. **Сообщение без просьбы — не задача.** Информационное («прими к сведению»,
   рассылка канона) закрывается ответом «принято» одной строкой — и ход
   ЗАВЕРШАЕТСЯ. Крутиться над ним, перечитывать канон и перестраивать планы
   не нужно.
2. **Рассылающий обязан пометить намерение.** Информационная рассылка
   начинается со слов «К сведению, действий не требуется». Просьба — содержит
   явное «что нужно от тебя» и одного адресата ответа.
3. **Закончил ход — заверши ход.** Нет действия и нет вопроса — сессия молчит
   и ждёт входящих. Пустая работа ради «занятости» — дефект, о нём сигналят
   архитектору.
4. Хендоффы — по `templates/handoff.md`, маршрут — по уставу
   (воркер → лид → тестировщик → архитектор).
5. **Очередь ходов: не буди толпу.** Сообщение будит получателя и запускает
   его ход; несколько писем разом = несколько сессий одновременно просят
   модель и стоят в очереди за лимитами — снаружи это выглядит «все зависли»
   (сбой 14.08.2026, вечер). Поэтому: одновременно активных ходов в команде —
   один-два; следующего будят, когда предыдущий отдал ход; рассылок «всем
   сразу» не бывает.
6. **Канон — в файл, не в рассылку.** Информационное (правила, канон,
   договорённости) кладётся в устав/мандаты и читается при следующем
   естественном пробуждении. Сообщением будят только того, от кого нужен
   ход прямо сейчас.

## Механика связи (как это делается руками)

- **Отправить сообщение сессии:** инструмент `send_message` из набора
  управления сессиями (`mcp: ccd_session_mgmt`); адресат — `session_id` из
  `list_sessions`, ищи по НАЗВАНИЮ из таблицы выше. Больше ничего не нужно:
  ни файлов, ни особых каналов.
- **Ответить на входящее письмо:** отправитель подписан в самом письме
  (`Message from …` + ссылка) — искать его по списку не надо. Отвечай тем же
  `send_message` ТОЛЬКО если в письме есть вопрос или просьба ответить.
- **«Принято» — это НЕ письмо.** На информационное входящее достаточно одной
  строки в СВОЁМ чате и конца хода: отправитель не ждёт ответа, а ответное
  письмо разбудило бы его впустую (см. правило 5).
- Нет инструмента `send_message` в списке — он подгружается поиском
  инструментов (ToolSearch) по имени; не нашёлся — скажи об этом в своём
  чате и заверши ход, не изобретай обходов.
