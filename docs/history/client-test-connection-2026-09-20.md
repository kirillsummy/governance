# Подключение client-app к тестовому адресу · 20.09.2026

По поручению владельца подготовлено отдельное размещение приложения на
`https://201.51.9.79/client/`. Проверку страниц, входа и заказов выполняет
владелец. Автотесты не запускать; реальные SMS и платежи согласовываются отдельно.

## Опубликовано

В `client-app/work` и `client-app/test` находится один commit
[`dd14eded75baebd3730d61389517fac97a89bc2a`](https://github.com/kirillsummy/client-app/commit/dd14eded75baebd3730d61389517fac97a89bc2a):

- `deploy/compose.test.yml`: отдельный сервис интерфейса/BFF, loopback-порт
  5191, сеть `summy-internal`, тестовый backend `gateway:8000`;
- origin `https://201.51.9.79`, публичное демо отключено, токен только серверный;
- Docker-сборка больше не запускает `npm test`; тесты остались отдельной командой;
- шаблон окружения без секретов и [инструкция запуска/отката](https://github.com/kirillsummy/client-app/blob/dd14eded75baebd3730d61389517fac97a89bc2a/docs/test-server.md).

Существующий nginx-фрагмент сохраняет префикс `/client/`, включая `/client/api/`,
и направляет оба в BFF. `/client` перенаправляется на `/client/`.

## Deployment пока не выполнен

Сервер отверг ключ `summy_vps` для root и указанного владельцем пользователя
`summy` с `Permission denied (publickey)`. Нужен разрешённый SSH-ключ либо
добавление соответствующего публичного ключа через консоль сервера.

Конфигурация nginx, контейнеры, БД и окружение сервера в этой задаче не менялись.
Сборка, автотесты, пользовательские сценарии, SMS и платежи не запускались.
Production-ветка client-app осталась на `4a3a245`; остальные продукты не менялись.

После восстановления доступа: точечно сверить действующие nginx/backend/миграции,
настроить тестовый токен без вывода секретов, собрать отдельный сервис, сохранить
конфигурацию nginx для отката и подключить location только в server-блок 443.
Сохранить существующие Basic Auth, TLS и noindex. Перед reload проверить синтаксис
nginx. Не включать реальные внешние интеграции и не восстанавливать БД из дампа.

## Последнее дополнение: локальное демо

На исходном ПК 20.09.2026 после сообщения `Failed to fetch` запущены два
локальных процесса из `work/client-app-current`: интерфейс Vite на
`http://127.0.0.1:5190/client/` и демо-BFF на `127.0.0.1:5191`.
Зависимости установлены через `npm ci`; подтверждены запуск процессов и
прослушивание портов. Пользовательские сценарии и автотесты не выполнялись.

Режим BFF: `CLIENT_DEMO=true`,
`CLIENT_PUBLIC_ORIGIN=http://127.0.0.1:5190`, `PORT=5191`.
Фиктивная демо-учётка: телефон `+79000000001`, код `123456` — это публичные
данные демонстрационного адаптера, а не реальные учётные данные.
SMS, записи в CRM и платежи не отправляются. Данные находятся в памяти процесса
и сбрасываются при его перезапуске. Демо слушает только loopback.

Это снимок на момент передачи: процессы могли завершиться. На другой ПК
запущенные процессы, зависимости и данные демо автоматически не переносятся.
Для повторного запуска использовать раздел «Локальная демонстрация» README
client-app; не включать этот режим на публичном тестовом сервере.

## Передача задачи на другой ПК

Этот документ и [журнал объединения](test-integration-2026-09-20.md) переданы
через [PR #66](https://github.com/kirillsummy/governance/pull/66), ветку
`feature/test-integration-20260920`. На момент передачи PR открыт, main ещё
не содержит эти дополнения. При продолжении сначала проверить статус PR:
после слияния читать main, до слияния — указанную ветку.

Следующей сессии:

1. Прочитать актуальные ограничения Governance, этот документ и
   [памятку экономии контекста](../../ai/TOKEN-EFFICIENCY.md). Не перечитывать
   все репозитории; сверить только актуальные SHA и необходимые настройки.
2. Использовать разрешённый SSH-доступ нового ПК и завершить размещение
   `/client/` по инструкции client-app `docs/test-server.md`. Проверить
   реальную конфигурацию стенда прежде, чем применять подготовленный compose.
3. Сборка и deployment разрешены только на тестовом сервере. Изменения
   продукта вести в work и включать в test с сохранением work. Production
   не трогать, автотесты не запускать. Вход, страницы и свои записи проверяет
   владелец; реальные SMS и платежи требуют отдельного согласования.
4. После фактического размещения обновить этот статус в Governance: указать
   развёрнутые SHA, изменения сервисов/миграций, способ отката и ограничения.
   Не считать наличие кода, сборку или запуск контейнера проверкой сценариев.

На этом исходная сессия завершает работу по поручению владельца; дальнейшего
анализа, deployment и проверок она не выполняет.
