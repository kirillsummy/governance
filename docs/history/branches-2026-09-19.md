# Исторический снимок веток · до объединения Governance

Включены **все 111 удалённых веток**, возвращённые paginated GitHub branches API
девяти репозиториев. Локальные старые refs и чужие worktree не объявлены актуальными
удалёнными ветками. Новая feature-ветка этой документации появится после снимка.

`+A / −B` — коммиты ветки сверх актуального default / коммиты default, отсутствующие
в ветке. Для шести локальных репозиториев «файлы» — различие деревьев двух SHA;
для workspace Compare API — изменения от merge-base (помечены MB). При 0 ahead
ветка не несёт уникальных коммитов относительно default, но её дерево может быть старым.
Числа не означают количество функций и не подтверждают использование ветки на сервере.

Назначение даётся по открытому PR, канону баз или доказанному совпадению SHA.
Если открытого PR нет, название ветки не переводится в выдуманную задачу.
«PR открыт» означает review-активность, не работу автора прямо сейчас.
Для остальных фактическое использование неизвестно. `protected` GitHub API
не заменяет организационный запрет прямого push.

## Метод и ограничения

Прочитаны GitHub `/repos/kirillsummy/{repo}`, `/branches?per_page=100&page=N`,
`/pulls?state=open&per_page=100`; в найденных репозиториях число открытых PR меньше 100.
Сравнение — git rev-list --left-right --count и git diff --name-only по SHA;
workspace — GitHub Compare API. Closed PR и время последней работы людей не исследовались.

После fetch у master-app возник конфликт stale ref `origin/test` с прежним вложенным
ref. Ничего не удалялось; актуальный test взят из GitHub API, его SHA уже имелся локально.
Локальные origin/HEAD у backend/master могут устареть; default выше получен с GitHub.

Для следующего обновления достаточно повторить metadata/branches/PR и сравнение SHA.
Не требуется checkout каждой ветки или запуск каждого приложения.


Список Governance выше исторический. [Текущая политика веток](../branches.md).
