# Ветки SUMMY

## Действующее решение владельца от 25.09.2026

У Governance одна ветка — `main`. В пяти продуктовых репозиториях работа собирается в `test`; production остаётся в уже существующей основной ветке. Новые `work`, `task/*` и тематические ветки не создаются. `singular` сохраняется только там, где отдельная полезная история не может безопасно войти в `test`. Перенос Git-истории в `test` сам по себе не означает выкладку на TEST-сервер.

Ветку `test` в один момент её обновляет один
назначенный ответственный. Перед переносом сверяют свежий удалённый SHA, проверяют уникальные коммиты и не переписывают опубликованную историю. Для production действуют решение Кирилла и стандартный релиз-процесс [устава](../CHARTER.md#релиз-процесс-стандарт). После интеграции ветку-источник удаляют; если в ней остаётся полезный, но несовместимый код, его сначала сохраняют в `singular` и записывают причину. Архив целиком в `test` не сливают.

| Репозиторий | Production/default | Интеграция | Исключение |
|---|---|---|---|
| backend | `dev` | `test` | `singular`: отдельная незавершённая линия SUMMY ID |
| crm | `main` | `test` | нет |
| client-app | `main` | `test` | нет |
| master-app | `feature/react-client` | `test` | нет |
| website | `main` | `test` | `singular`: альтернативные страницы лазера и мастера |

После очистки проверены удалённые головы: backend `test` — `7faad78`, CRM — `0f5b6e3`, client-app — `1c21906`, master-app — `6ad5d05`, website — `e790c7a`. Это Git SHA, а не версии запущенных контейнеров.

Имена `dev` и `feature/react-client` сохранены по уточнению владельца; временно созданные одноимённые копии `main` удалены. Имя `feature/react-client` здесь обозначает существующую production/default-ветку master-app, не разрешение создавать новые feature-ветки.

## Разбор веток 25.09.2026

- Из `work` в `test` перенесены доработки рекламаций и приложения клиента, включая backend 0141; CRM получила короткие подписи полей. Ветки задач с новыми памятками `AGENTS.md` включены в историю `test`, а правила работы приведены к этому решению.
- Документ `crm/feature/processes-complaints-spec` включён в `test`; документы `master-app/feature/master-v1-owner-decisions-2026-09-23` уже совпадали по содержимому с `test`, история ветки также включена.
- Старые локальные архивы CRM, client-app и master-app не сохраняются как ветки: они указывают на устаревшие деревья; содержимое, необходимое продуктам, уже находится в `test` или документации.
- `backend/singular` не включается: старый альтернативный механизм SUMMY ID меняет схему входа и миграции; разбор — [SUM-99](https://summy.youtrack.cloud/issue/SUM-99). `website/singular` не включается: альтернативные страницы и тексты требуют отдельного продуктового решения; разбор — [SUM-100](https://summy.youtrack.cloud/issue/SUM-100). Оба архива оставлены доступными до решения.
- Служебные репозитории `docs`, `context`, `workspace` известны по историческому реестру, но текущий SSH-доступ к ним не подтвердился (`Repository not found`); их ветки не изменялись и их состояние не объявляется проверенным.

До удаления исходных веток проверяется достижимость их коммитов из `test` либо явно документируется, почему устаревшая ветка снимается без переноса дерева. Автоматические тесты, сборки и проверки документации для этой реорганизации не запускались. Серверный deployment — отдельная операция.

[Историческая политика и снимки до очистки](history/branches-before-cleanup-2026-09-25.md) сохраняют прежние SHA, решения и ограничения для аудита.
