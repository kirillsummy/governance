## Модули и входы

`src/App.tsx`, api.ts и types.ts — клиент; `server/index.mjs` — BFF; `server/demo.mjs` — явная локальная демонстрация. Префикс `/client/`, API браузера `/client/api/*`, backend `/v1/client/*`.

Пазл `/client/play` (SUM-209, 02.10.2026) — клиентская игра в `src/game/`:
детерминированный движок (зерно + журнал ходов) и экран. С 04.10.2026
(client-app `4ca1dbe0e9274e07ab5046710720b8766be229e8`, backend
`e5fe9bb6bc685819bedd702d63dbce0d0056950b`, `0193_puzzle_games`) после входа по
телефону партия заводится на backend (`/v1/client/puzzle/games`: общее зерно
задания дня `summy-daily-<дата>`, случайное 32-битное для свободной партии,
зерно ссылки для поединка), журнал ходов уходит на проверку
(`/games/{id}/finish`): backend переигрывает его копией движка
(`app/domains/client_portal/puzzle_engine.py`, та же 32-битная арифметика и
порядок генератора — файлы меняются только вместе) и сам считает очки.
Рейтинги дня и недели — по заданиям дня, без имён. Без входа игра локальная.
Призов и начислений нет — решение владельца (SUM-96). Вход с сайта — кнопка
«Сыграть» (website `7733966`, тестовый флаг); студийный QR — существующий
генератор QR-кампаний CRM с целью `https://summy.ru/client/play`.

## Авторизация и данные

SMS OTP и связь с существующим CRM-клиентом проверяются backend. HttpOnly cookie хранится у BFF, allowlist и origin ограничивают запросы. Клиент получает только свои заказы; запрос отмены обрабатывает администратор. Цена/свободное время/статус оплаты не определяются браузером.

## Оплата и незавершённое

В просмотренном feature есть страница /client/pay/:id и ссылка Яндекс sandbox либо отключённая заглушка. Последнее требование — заменить ссылку привязкой карты. Реализация binding, касса и внешний e2e не подтверждены; правило подтверждения каждого списания/автосписания ещё не выбрано.

В `client-app/work` `7d877b4` и `f3169d5` подготовлен визуальный выбор СБП, карты и Mir Pay на странице заказа и локальный dev-only предпросмотр `/client/dev/payment-preview` без входа. Рабочая страница показывает сумму из backend; предпросмотр — вымышленный заказ. Окно показывает предполагаемый следующий шаг, но не создаёт платёж и не меняет финансовые состояния. Бизнес-вопросы о моменте и сумме оплаты, провайдере, смысле Mir Pay и возвратах — в [SUM-117](https://summy.youtrack.cloud/issue/SUM-117); серверный контур карт и СБП — в [SUM-79](https://summy.youtrack.cloud/issue/SUM-79). Коммиты `work` не подтверждают доставку в `test` или среду.

С 30.09.2026 по решению владельца («Сделай просто два варианта оплаты рядом. Две кнопки на оплату айклинс и новая с картами») этот этап слит в `client-app/test` `8ad3fce7bc8b652792a8533ee7c8a87eb9d229eb`, ветка `work` удалена. На `/client/pay/:id` рядом стоят два действия; на узком экране они переносятся вертикально. Первое — действующая ссылка `payment.url` при `payment.mode=live`: backend отдаёт тестовую sandbox-ссылку «Яндекс Пэй / Сплит» (`order_payments.payment_url`), поэтому кнопка названа так; ссылки оплаты YClients в контракте клиентского приложения нет, и без отдельного решения её так не называют. Без живой ссылки кнопка неактивна. Второе — «Оплата картой»: окно предварительного выбора карты, СБП и Mir Pay без запроса к API; кнопка в окне неактивна с подписью «Оплата пока недоступна». Платёж не создаётся, реквизиты карты не собираются, `paymentStatus` и чек не меняются. Сплит Т-Банка, автоматическое списание и серверный контур остаются в [SUM-79](https://summy.youtrack.cloud/issue/SUM-79).

## Конфигурация и проверки

Подготовка отдельного тестового `/client/`, SHA конфигурации и блокировка SSH:
[журнал подключения 20.09.2026](../history/client-test-connection-2026-09-20.md).

CLIENT_BACKEND_URL/TOKEN, CLIENT_PUBLIC_ORIGIN; CLIENT_DEMO только loopback, без реальных SMS/CRM/платежей. npm test, build, format:check. `https://summy.ru/client/` — предполагаемый публичный адрес, не подтверждённый deployment.
Демо-адаптер подключается только явно; фиктивная история CRM заранее задана
только документированной демо-учётной записи. Просроченные challenge и
сессии удаляются из памяти демо-процесса. Live BFF не подменяет ошибку
backend демонстрационными данными.
