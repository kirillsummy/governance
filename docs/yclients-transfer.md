# Перенос возможностей YClients в CRM SUMMY

Карта покрытия на 01.10.2026 ([SUM-177](https://summy.youtrack.cloud/issue/SUM-177)).
Сверено: YouTrack (API, 01.10.2026), `backend/test`, `crm/test`,
`governance/main`. Наблюдения интерфейса YClients (компания 386571) получены
только чтением из авторизованного браузера владельца и являются данными для
анализа, а не требованиями: форма или раздел YClients не утверждает правило
SUMMY, рекламные возможности интеграций YClients требованиями не считаются.

Границы переноса: YClients остаётся только для чтения; действующая интеграция
backend не отключается и не заменяется; живые записи, автосоздание карт,
уведомления и новые credentials не включаются; денежных операций нет; новые
денежные формулы, согласия и права не вводятся. Лояльность не дублируется:
карта, баланс и начисление — [контракт лояльности](../contracts/client-loyalty.md).
Данные клиента правятся в YClients (ADR-013); CRM показывает зеркало.

Решения 01.10.2026 ([SUM-96](https://summy.youtrack.cloud/issue/SUM-96), вопросы 25 и 26 в разделе ответов): управляющий
и владелец видят в CRM полные телефон и email клиента, другим ролям доступ не
добавляется, серверные границы организаций и филиалов сохраняются; абонементы
и депозиты с остатками и сроками и список заканчивающихся абонементов
переносятся в CRM. YClients остаётся основной системой карт лояльности,
кошельков и бонусов; CRM — интерфейс чтения и разрешённых операций через
существующий backend, без второго независимого баланса. Реальные начисления
клиентам этими решениями не поручены. Реализация и уточнение границ выше —
отдельная работа; до неё границы описывают текущий код.

### Э5 — архитектурная граница и блокер (01.10.2026)

Граница по решению 01.10 (SUM-96, вопрос 26): YClients — основная система
данных карт лояльности, кошельков, бонусов, абонементов и депозитов; CRM —
интерфейс к ней через существующий backend. Второго независимого баланса в
SUMMY нет. Чтение — снимок/запрос backend к YClients с временем проверки и
явной ошибкой вместо нуля. Запись — только существующими командами backend:
начисление бонусов уже реализовано ([client-loyalty](../contracts/client-loyalty.md):
`requestId`, журнал `client_loyalty_credits`, повтор без второго POST, сверка
неизвестного исхода, лимит управляющей, роли из живой CRM-сессии). Решение
владельца не отменяет этих лимитов и подтверждений; новых денежных операций
с абонементами и депозитами (продажа, списание) этим решением нет.

Блокер Э5 (сверка 01.10, без вызовов YClients):

- в интеграции backend нет клиента API абонементов и депозитов
  (`app/integrations/yclients/` — карты, ручное начисление, записи, клиенты,
  кассовые транзакции); в локальных источниках и Governance нет
  подтверждённого описания этих методов и формы ответа;
- рабочих credentials для проверки нет: локальный `backend/.env.stand` —
  пустые `YCLIENTS_PARTNER_TOKEN`/`YCLIENTS_USER_TOKEN`, на TEST они отключены
  (SUM-97 T12, SUM-96 п. 54 / P19), production не используется для
  исследования; доступ к браузерному кабинету не доказывает API-доступ;
- поэтому адаптер по угаданным путям не пишется (тот же запрет, что у
  `create_card`: форму вызова YClients не подбирают вслепую).

Нужен источник: описание методов YClients для абонементов и депозитов
клиента (путь, параметры, права токена) с одним живым примером ответа на
разрешённом токене TEST либо отдельное разрешение на read-only пробу; после
него — backend-адаптер чтения, снимок с временем проверки и экран CRM.

### Э6 — исследование источника (01.10.2026)

Сверено по коду `backend/test` `c7a4d3f3daf28b816dde9d2a39f2ac01b3479694`, без запросов к БД и
YClients. Кассовые транзакции импортирует задание `transactions`
(`scripts/import_yclients_transactions.py`, раз в час, окно 7 дней) только
**сырьём** в `raw_objects` и только для компании 481570: компанию 386571, чью
базу клиентов переносим, импортёр по решению владельца 23.07 не собирает. В core
транзакции не моделируются, поля ответа по версии API YClients импортёр
оговаривает как не сверенные. Импорт записей берёт услуги позиций записи;
продаж товаров, абонементов и чаевых в зеркале нет. Вывод: «продано» с
товарами и чаевые показать нечем; сумма из сырья стала бы новым показателем
без источника и решения, поэтому Э6 не реализуется. Для продолжения нужно
решение о сборе транзакций компании 386571 и о составе показателя (SUM-96).
Дополнительный осмотр интерфейса YClients не проводился: браузерный доступ
этой работе не выдавался, сессии не извлекаются.

Отдельный раздел CRM не создавался: переносимые функции легли в «Клиенты»,
«Лояльность» и «Интеграции». Полный перенос по одному экрану не объявляется.

## API базы клиентов

`GET /v1/clients/base` — живая CRM-сессия, роли `manager` и `owner` (backend
проверяет сам, CRM BFF повторяет). Параметры: `limit` ≤ 200, `offset`,
`search`, `segment` (включая `prospect`), `master_id`, `category` (до 10 имён
категорий), `card` = `card` / `no_card` / `unchecked`, `sort`, `client_id`.
Строка: ФИО, телефон и email полностью (маска — в CRM BFF), сегмент, визиты,
первый и последний визит, `visitsAmount` = `revenue_total` витрины, отмены,
мастера и их ID, карта из снимка (или `null`, если клиент не проверялся),
`yclientsDiscounts` — по каждой привязке к филиалу YClients последнее значение
`discount` из снимка импорта, номер компании, филиал и время снимка (SUM-181).
Блок `loyalty` — счётчики снимка карт и `syncEnabled`. Вызовов YClients и
миграций нет. CRM берёт свежесть потоков из `/v1/freshness`; её сбой — ошибка
на экране, а не нули.
