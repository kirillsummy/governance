# Production-кандидат: CRM, пустые «Процессы» у управляющей (01.10.2026)

Статус: **подготовлен, не утверждён, production не менялся**. Инцидент
production после [RC5 редакции 2](production-rc5-deployment-2026-09-30.md):
у управляющей пустой раздел «Процессы». Выкладка — только после утверждения
Кириллом по [уставу](../../CHARTER.md#релиз-процесс-стандарт) и после
проверок из раздела ниже.

## Доказанная причина

Диагностика production 01.10.2026 — только чтение: SSH с проверенным host key,
журналы контейнеров и запросы к БД через образ API в транзакции `read only`.
Персональные данные, номера учёток, телефоны и сессии не выводились.

- Работают RC5: backend `10e0dd53355605a2d9ae7daa1f3ba45ee1c4fb95`,
  CRM `086e8c71de92668caf57a8f1af9b605f829d2125`; контейнеры поднялись
  30.09 и не перезапускались.
- Допуск сотрудницы найден в `gateway_admin_access` по отображаемому имени:
  роль `manager`, допуск активен, выданы оба действующих филиала,
  переопределений раздела «Процессы» для роли нет. Права и филиалы в порядке.
- Журнал API за 16 часов: `GET /v1/processes` — 60 ответов 200, ошибок 4xx/5xx
  по процессам нет. Все 14 загрузок экрана шли с `assignee=me`.
- Тот же сервисный отбор backend для её допуска: без отбора по ответственному
  19 активных и 268 закрытых процессов, с `assignee=me` — 0 и 0.
- Источник — CRM `98973b0` (SUM-176, вошёл в RC5): фильтр «Ответственный»
  открывал «Процессы» со значением «я». Доска, список и календарь отправляют
  `assignee=me`, личный отбор учитывает только принятые рекламации, личные
  задания и именные назначения. У управляющей таких процессов нет, поэтому
  экран пуст. Видимые ей роль-назначенные процессы
  [личными не считаются](../../contracts/process-personal-view.md).

## Исправление

Только CRM, файл `src/components/process/processes-screen.tsx`: фильтр
«Ответственный» по умолчанию «все», в адрес пишется любое значение, кроме
«все». «Ответственный: я» со счётчиком и выбор сотрудника сохранены. Права,
ACL, серверный отбор, филиалы, счётчик у пункта меню и production-данные
не менялись.

## Совместимость

- backend, master-app, website, client-app и БД `0160_daily_processes` не
  меняются, миграций нет. CRM вызывает те же ручки backend RC5, что и раньше;
  `assignee=me` и `mine=true` по-прежнему поддерживаются.
- Вход `gateway` и `legacy`: без серверной сессии фильтр уже был «все»,
  поведение не меняется.
- Старые ссылки без `assignee` открывают общий список; ссылки с
  `assignee=<id>` или `assignee=me` сохраняют выбор.
