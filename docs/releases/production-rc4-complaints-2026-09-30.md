# SUM-174 — production-кандидат RC4 «брак и рекламации», 30.09.2026

**Статус: кандидат подготовлен, собран и проверен; production не менялся.**
Production-ветки, релизные теги, рабочие сервисы и production-БД остались
в состоянии RC2. Переключение возможно только после утверждения именно этого
номера и состава по [CHARTER](../../CHARTER.md#релиз-процесс-стандарт).

Задача: [SUM-174](https://summy.youtrack.cloud/issue/SUM-174). Исходные задачи:
[SUM-119](https://summy.youtrack.cloud/issue/SUM-119),
[SUM-140](https://summy.youtrack.cloud/issue/SUM-140),
[SUM-83](https://summy.youtrack.cloud/issue/SUM-83),
[SUM-111](https://summy.youtrack.cloud/issue/SUM-111). Предыдущий релиз:
[RC2](production-rc2-deployment-2026-09-28.md).

Поручение владельца 30.09.2026: перенести в production только изменения брака
и рекламаций, уже поставленные на TEST, сохранив данные и работающие функции.
Весь TEST не переносится.

## Что нужно решить до переключения

1. **Утвердить RC4 по номеру и составу** и снять для этого объёма паузу
   production, записанную после RC2 в [текущем состоянии](../current-state.md).
2. **Удаление рекламации в production работать не будет.** SUM-140 по своему
   требованию принимает удаление только с серверной CRM-сессией. Production
   CRM работает с прежним входом (`legacy`), такой сессии у него нет. В RC4
   кнопка при прежнем входе скрыта, сервер на прямой запрос отвечает 403.
   Чтобы удаление заработало, нужно отдельное решение: перевести CRM на
   gateway-вход либо разрешить удаление по роли прежнего входа. Второе
   ослабляет записанное требование SUM-140 и в RC4 не вводилось.
3. **Штраф по рекламации станет виден мастеру в ленте заработка.** Это
   следствие ревизии 0149, которая стоит в общем журнале раньше ревизии
   рекламаций 0151, и обойти её без разрыва журнала нельзя. Зарплатная сводка
   такие штрафы вычитала и раньше. В production сейчас нет ни одного
   выписанного штрафа, поэтому прошлые суммы не меняются. Это денежное
   правило — решение Кирилла.
4. **Схема чужих задач придёт без их кода.** Ревизии 0144–0150 и 0152–0154
   (закрытие записи, перенос, зарплата, ресурсы, лояльность) применяются,
   потому что журнал Alembic один. Их функции в RC4 не входят и не
   включаются; ниже показано, чем это закрыто.
5. После релиза два переключателя RC4 нужно перенести в `test` и задать на
   TEST значения `STAFF_PENALTY_PAYROLL_ENABLED=true` и
   `UNRELEASED_PROCESS_TYPES=` (пусто), как это делалось с запретами RC2.

## Порядок выкладки

Скрипты `rc4-stage.py`, `rc4-deploy.py`, `rc4-postdeploy-check.py` получены
из скриптов RC2 и лежат в `/opt/summy-rc4-build-20260930/release` на TEST.
На production они не запускались.

1. Получить утверждение RC4. Снова прочитать production: версии RC2, ревизия
   0143, образы `67d63aa6…` и `f7652b25…`, свободное место. Любое отличие —
   остановка.
2. Создать `/root/releases/rc4-20260930` с правами root. Передать два архива
   исходников, два архива образов и три скрипта; сверить SHA256.
3. `rc4-stage.py`: подготовить каталоги backend и CRM рядом с рабочими,
   скопировать действующие `.env` без изменений, вписать образы и флаги,
   сверить неизменность сетей, портов, томов и команд.
4. `docker load` двух образов; сверить метку ревизии и идентификаторы.
   Пометить текущие образы тегами `pre-rc4-20260930`.
5. Записать `RELEASE_GO`. `rc4-deploy.py backend`: остановить API и sync,
   снять счётчики таблиц, сделать свежий дамп штатным скриптом и прочитать
   его `pg_restore` целиком, поменять каталоги, применить 12 ревизий по
   одной со сверкой после каждой, сравнить счётчики, поднять API и sync,
   дождаться `/ready` и версии. Ожидаемая недоступность API — 3–4 минуты.
6. `rc4-deploy.py crm`: поменять каталог и контейнер CRM, дождаться health с
   SHA кандидата. При сбое скрипт сам возвращает прежний CRM.
7. `rc4-postdeploy-check.py`: версии четырёх продуктов, ревизия 0155, флаги
   API и sync, скрытые виды, маршруты рекламаций, схема закрепления,
   закрытые маршруты RC2, sync.
8. Продвинуть `backend/dev` и `crm/main` fast-forward на SHA кандидата,

| Момент | Действие |
| --- | --- |
| Сбой до миграций | Скрипт возвращает каталог и запускает прежние контейнеры; схема не менялась |
| Сбой на ревизии | Писатели остановлены, новых записей нет: скрипт откатывает схему до 0143 образом кандидата, возвращает каталог и запускает RC2. Проверено репетицией |
